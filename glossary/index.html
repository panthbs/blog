อภิธานศัพท์

ศัพท์เฉพาะที่ผมใช้ในบล็อก เรียงตามตัวอักษร แต่ละคำลิงก์กลับไปหาบทความที่อธิบายเป็นครั้งแรกครับ

[CLS] token (ชิ้นแรก)
ชิ้นพิเศษที่ tokenizer ใส่ไว้หน้าข้อความ (XLM-R เขียน <s>) เวกเตอร์ของมันมักถูกใช้แทนทั้งข้อความ แต่จะสรุปประโยคได้ก็ต่อเมื่อถูกฝึกให้ทำหน้าที่นั้น บท 4.1
[UNK]
token พิเศษแทนข้อความที่ tokenizer ไม่รู้จัก (บางโมเดลเขียนว่า <unk>) ข้อมูลส่วนนั้นหายไปจากมุมมองของโมเดล บท 1.2
80/10/10
กติกาของ BERT: ชิ้นที่ถูกเลือก 80% เปลี่ยนเป็น mask token 10% เปลี่ยนเป็นชิ้นสุ่ม 10% คงเดิม เพราะตอนใช้งานจริงไม่มี mask token บท 3.3
A/B testing
แบ่งผู้ใช้จริงส่วนหนึ่งไปใช้ระบบใหม่ ที่เหลือใช้ระบบเดิม แล้วเทียบ metric จากพฤติกรรมจริง เช่น อัตราการสั่งซื้อ บท 4.3
accuracy
สัดส่วนข้อที่ทายถูก หลอกได้ง่ายเมื่อหมวดหนึ่งมีจำนวนมากกว่าหมวดอื่นมาก บท 1.4
add-one smoothing (Laplace smoothing)
บวกหนึ่งให้ทุกคู่ก่อนหาร (และบวกขนาดคลังศัพท์ที่ตัวส่วน) เพื่อไม่ให้คู่ที่ไม่เคยเห็นได้ศูนย์ บท 1.3
agent (เอเจนต์)
ระบบที่วนรอบ สังเกต → คิด → ลงมือ โดยให้โมเดลเลือกเองว่าจะเรียกเครื่องมือไหนหรือจะตอบเลย แล้วเอาผลของการลงมือกลับมาพิจารณาในรอบถัดไป บท 5.1
alignment (embeddings)
ตัววัดว่าคู่ที่ถูกอยู่ใกล้กันแค่ไหน (ระยะกำลังสองเฉลี่ย ยิ่งต่ำยิ่งใกล้) บท 4.2
alignment tax (ภาษีของการ align)
ความสามารถบางอย่างที่ตกลงเมื่อฝึกให้โมเดลทำตามความชอบ บท 3.6
allocative harm (ความเสียหายเชิงการจัดสรร)
เมื่อผลของระบบทำให้แบ่งโอกาสหรือทรัพยากรไม่เป็นธรรม เช่น ตัวคัดใบสมัครงานที่เอียงข้าง บท 5.3
anisotropy (กรวยแคบ)
สมบัติที่เวกเตอร์ของโมเดลชี้ไปทางใกล้ ๆ กันหมด ข้อความที่ไม่เกี่ยวกันก็ยังได้ cosine สูงกว่าเวกเตอร์สุ่ม บท 2.2
annotation guideline (กติกาการติดป้าย)
เอกสารที่นิยามว่าป้ายแต่ละแบบแปลว่าอะไร พร้อมตัวอย่างที่ผ่านและไม่ผ่าน เขียนก่อนติดป้ายข้อแรก ถ้าความสอดคล้องระหว่างผู้ติดป้ายต่ำ ปัญหามักอยู่ที่เอกสารนี้ บท 4.3
answer contained
ได้ 1 เมื่อคำตอบมาตรฐานปรากฏอยู่ในคำตอบของโมเดล ใจดีกับคำตอบยาว แต่ให้ 0 กับคำตอบสั้นที่ถูก เช่น "สตูล" เทียบ "จังหวัดสตูล" บท 4.4
approximate nearest neighbour (ANN) search (การค้นเพื่อนบ้านใกล้สุดแบบประมาณ)
หาเวกเตอร์ที่ใกล้คำถามที่สุดโดยไม่เทียบกับทุกตัว แลกความเร็วกับโอกาสพลาดบางตัวที่ exact search จะเจอ วัดด้วย recall เทียบกับ exact search บท 6.4
argument validity
สัดส่วน tool call ที่ผ่านการตรวจ schema ก่อนรัน บท 5.1
attention
กลไกที่ให้ decoder ให้คะแนนโน้ตของทุกคำต้นทางใหม่ทุกครั้งที่จะเขียนคำ แล้วผสมโน้ตตามน้ำหนัก แทนการพึ่งเวกเตอร์ตัวเดียว บท 2.4
attention mask
แถวเลข 1 กับ 0 บอกว่าช่องไหนเป็นชิ้นจริง ต้องส่งให้โมเดลเพื่อไม่ให้มองช่องเติม และต้องใช้ตอนเฉลี่ย ลืมแล้วโปรแกรมไม่ฟ้องแต่ผลเพี้ยน บท 4.1
Auto-Merge
การค้นของ HiChunk ที่แทน chunk ลูกที่ดึงมาด้วย section พ่อทั้งก้อน เมื่อดึงลูกมาแล้วอย่างน้อยสองท่อน ลูกยาวพอเมื่อเทียบกับพ่อ และงบที่เหลือพอใส่พ่อ hichunk
average precision (AP) / MAP
AP คือค่าเฉลี่ยของ precision ณ ทุกอันดับที่เจอ gold ของคำถามหนึ่งข้อ MAP คือค่าเฉลี่ยของ AP ข้ามคำถาม บท 4.3
backpropagation
วิธีหา gradient ของทุก weight โดยส่งความผิดจากปลายย้อนทีละชั้นด้วย chain rule ไม่ใช่ตัวขยับ weight เอง บท 2.3
bag of embeddings (ถุงเวกเตอร์คำ)
ตัวจัดหมวดที่เฉลี่ยเวกเตอร์ของทุกคำเป็นเวกเตอร์เดียวแล้วส่งเข้าโครงข่าย ไม่สนลำดับคำ บท 2.3
bag of words (ถุงคำ)
แทนข้อความด้วยจำนวนครั้งที่แต่ละคำปรากฏ ทิ้งลำดับทั้งหมด อร่อย|ไม่|แพง กับ แพง|ไม่|อร่อย จึงเป็นถุงเดียวกัน บท 1.4
base model (โมเดลตั้งต้น)
โมเดลที่ฝึกแค่ทายชิ้นถัดไป เขียนต่อข้อความได้แต่ยังไม่ได้ฝึกให้ทำตามคำสั่งแบบผู้ช่วย บท 3.4
beam search (ค้นหาแบบลำแสง)
วิธีเลือกคำที่เก็บประโยคที่ยังเขียนไม่จบไว้ k แบบที่ดีที่สุดในทุกก้าว แล้วเลือกประโยคที่คะแนนรวมดีที่สุดตอนจบ บท 2.4
benchmark (ชุดทดสอบมาตรฐาน)
ชุดคำถามพร้อมเฉลยที่ใช้เทียบโมเดลหลายตัวด้วยวิธีเดียวกัน เช่น ข้อสอบปรนัยที่วัดด้วย accuracy บท 3.7
BERTScore
metric ที่แปลง token เป็นเวกเตอร์ด้วยโมเดลภาษา แล้วจับคู่ token ที่ cosine สูงสุดระหว่างสองประโยค คะแนนดิบอยู่ในช่วงแคบ บท 3.7
bi-encoder
เข้ารหัสคำค้นกับเอกสารแยกกันเป็นเวกเตอร์ แล้ววัดความใกล้ เวกเตอร์ของเอกสารคำนวณเก็บไว้ล่วงหน้าได้ บท 4.1
bigram (คู่คำ)
n-gram ที่ n = 2 คือคู่หน่วยที่อยู่ติดกัน บท 1.3
BIO tagging
ติดป้าย B ที่คำแรกของชื่อ I ที่คำถัดไปในชื่อเดียวกัน และ O ที่คำนอกชื่อ พร้อมประเภท เช่น B-PERSON ป้าย B ทำให้แยกชื่อที่อยู่ติดกันได้ บท 5.4
bits per character (บิตต่อตัวอักษร)
จำนวนบิตทั้งหมดที่โมเดลต้องใช้กับข้อความทดสอบหารด้วยจำนวนตัวอักษร ใช้เทียบโมเดลที่ตัดข้อความต่างกัน บท 1.3
BLEU
metric งานแปลที่นับ n-gram ของคำ (1 ถึง 4) ในคำแปลของโมเดลที่ตรงกับคำแปลอ้างอิง แบบ clip จำนวน แล้วคูณ brevity penalty คะแนนภาษาไทยขึ้นกับตัวตัดคำ บท 3.7
BM25
สูตรให้คะแนนเอกสารจากคำที่ตรงกับคำค้น เพิ่มจาก tf-idf สองอย่าง คือ saturation (k1) และการหักความยาวเอกสาร (b) บท 1.5
Boolean retrieval (การค้นแบบบูลีน)
ค้นด้วยเงื่อนไขว่ามีคำหรือไม่มีคำ ต่อด้วย AND / OR / NOT ผลคือเจอหรือไม่เจอ ไม่มีลำดับ บท 1.5
bottleneck (คอขวด)
ข้อจำกัดของ encoder-decoder แบบเดิมที่ต้องอัดทั้งประโยคลงเวกเตอร์ขนาดตายตัวตัวเดียว ประโยคยาวจึงเสียข้อมูล บท 2.4
BPE (Byte Pair Encoding)
วิธีสร้างคลังชิ้นคำโดยนับคู่ที่อยู่ติดกันแล้วรวมคู่ที่เจอบ่อยที่สุดซ้ำ ๆ ผลคือลำดับ merge ที่ใช้ตามลำดับเดิมตอนตัดข้อความใหม่ บท 1.2
Bradley–Terry model
แบบจำลองที่บอกว่าความน่าจะเป็นที่ A ดีกว่า B = sigmoid ของผลต่างคะแนน เหมือน logistic regression บนผลต่าง บท 3.6
brevity penalty (บทลงโทษความสั้น)
ตัวคูณใน BLEU ที่ลดคะแนนเมื่อคำแปลของโมเดลรวมแล้วสั้นกว่าคำแปลอ้างอิง บท 3.7
budget forcing (บังคับหยุดคิด)
แทรกคำหรือแท็กให้โมเดลหยุดคิดแล้วตอบเมื่อถึงงบ บท 5.2
byte-level BPE
BPE ที่เริ่มจากไบต์ 256 ค่าแทนตัวอักษร ไม่มีตัวอักษรที่ไม่รู้จัก แต่ token หนึ่งอาจถือไบต์ไม่ครบตัวอักษร ถอดเดี่ยว ๆ แล้วได้ � บท 1.2
causal language modeling (CLM)
เกมทายชิ้นถัดไปจากชิ้นทางซ้ายเท่านั้น ทุกตำแหน่งในประโยคเป็นข้อสอบ ใช้ฝึก GPT และโมเดลตระกูล decoder บท 3.3
causal mask
การเติม −∞ ให้คะแนนของคู่ที่ key อยู่หลัง query ก่อน softmax ทำให้แต่ละตำแหน่งมองได้แค่ตัวเองกับคำก่อนหน้า ใช้ในโมเดลที่ฝึกทายคำถัดไป บท 3.1
chain of thought (CoT) (ลำดับความคิด)
ข้อความขั้นกลางที่โมเดลเขียนก่อนคำตอบสุดท้าย ทำให้ได้คำนวณมากขึ้นก่อนตอบ บท 5.2
chain rule (derivative) (กฎลูกโซ่ของอนุพันธ์)
ความชันของฟังก์ชันที่ต่อกันหลายชั้นเท่ากับผลคูณของความชันเฉพาะจุดตามทาง (คนละความหมายกับกฎลูกโซ่ของความน่าจะเป็นในบท 1.3) บท 2.3
chain rule (probability) (กฎลูกโซ่ของความน่าจะเป็น)
การแตกความน่าจะเป็นของทั้งประโยคเป็นผลคูณของการเดาทีละคำ โดยแต่ละคำขึ้นกับทุกคำก่อนหน้า บท 1.3
character n-gram
ชิ้นตัวอักษรที่ติดกัน n ตัว ใช้เป็นหน่วยในดัชนีแทนคำได้ บท 1.5
chat template (แม่แบบแชต)
กติกาที่ห่อข้อความของแต่ละบทบาทด้วย token พิเศษก่อนส่งเข้าโมเดลแชต บางแม่แบบเติมข้อมูลอย่างวันที่ให้เอง บท 3.4
chosen / rejected (คำตอบที่ถูกเลือก / ไม่ถูกเลือก)
สองฝั่งของคู่ความชอบ บท 3.6
chrF
F-score ของ character n-gram (1 ถึง 6 ตัว) ที่ให้ recall หนักกว่า precision (β = 2) ลบช่องว่างก่อนนับ จึงไม่ขึ้นกับการตัดคำ บท 3.7
chrF++
chrF ที่เพิ่ม n-gram ของคำ (1 ถึง 2 คำ) เข้าไป ส่วนของคำจึงขึ้นกับการตัดคำ บท 3.7
chunk (ท่อนเอกสาร)
ข้อความท่อนสั้นที่หั่นจากเอกสารยาว เพื่อค้นทีละท่อนและใส่ลงใน prompt ได้พอดี บท 4.4
classification head (หัวจำแนก)
ชั้นเล็ก ๆ ที่ต่อไว้บนเวกเตอร์ของข้อความ เพื่อแปลงเป็นคะแนนของแต่ละหมวดแล้วเข้า softmax เริ่มจากค่าสุ่ม บท 3.5
closed book / open book (สอบปิดตำรา / สอบเปิดตำรา)
ถามโมเดลโดยไม่ให้เอกสาร (ปิดตำรา) เทียบกับถามพร้อมเอกสารที่เกี่ยวข้อง (เปิดตำรา) บท 4.4
co-occurrence matrix (ตารางนับคำรอบข้าง)
ตารางที่แถวคือคำ คอลัมน์คือคำรอบข้าง ช่องคือจำนวนครั้งที่อยู่ในหน้าต่างเดียวกัน แต่ละแถวใช้เป็นเวกเตอร์ของคำได้ บท 2.1
code point
เลขประจำตัวของสัญลักษณ์หนึ่งตัวในมาตรฐาน Unicode เช่น ค คือ U+0E04 คอมพิวเตอร์เก็บข้อความเป็นลำดับของ code point บท 1.1
code-switching (การสลับภาษา)
การที่ข้อความสลับหรือปนหลายภาษา เช่นคำตอบที่ควรเป็นภาษาไทยแต่มีภาษาอื่นปนออกมา บท 3.4
collapsed tree
วิธีค้นใน tree ของ RAPTOR ที่เทโหนดทุกชั้น (ท่อนดิบและบทสรุป) มารวมกัน แล้วเลือกตาม cosine similarity กับคำถามจนเต็มงบ token raptor
collocation (คำที่มักมาคู่กัน)
คู่คำที่ปรากฏด้วยกันบ่อยกว่าความบังเอิญมาก หาได้ด้วย PMI บนคำที่อยู่ติดกัน ใช้จับสำนวนและคำประสม รวมถึงจับคำที่สะกดถูกแต่ใช้ผิดที่ บท 2.1
combining mark
code point ที่ไม่ยืนเดี่ยว แต่วาดทับตัวข้างหน้า เช่น สระบน สระล่าง และวรรณยุกต์ของภาษาไทย บท 1.1
compounding error (ความผิดพลาดทบต้น)
ถ้าแต่ละขั้นสำเร็จด้วยความน่าจะเป็น p และเป็นอิสระกัน งาน n ขั้นสำเร็จเพียง p ยกกำลัง n วงยิ่งยาวยิ่งพังง่าย บท 5.1
confidence interval (ช่วงความเชื่อมั่น)
ช่วงของค่าที่น่าจะเป็นไปได้ของตัวเลขที่วัด เช่น ช่วงกลาง 95% ของผลต่างจาก bootstrap ถ้าคร่อมศูนย์ แปลว่ายังบอกไม่ได้ว่าใครดีกว่า บท 3.7
confusion matrix
ตารางที่แถวคือคำตอบจริง คอลัมน์คือสิ่งที่โมเดลทาย (บางตำราสลับกัน) ช่องทแยงคือทายถูก บท 1.4
constrained decoding
การจำกัดให้โมเดลสร้างได้แค่ข้อความที่อยู่ในชุดที่อนุญาต เช่น ชื่อ leaf ที่มีอยู่จริงในสารบัญ token ที่จะพาออกนอกชุดถูกปิดทิ้งทุกขั้น จึงไม่มีทางสร้าง id ที่ไม่มีอยู่จริง stair
context vector
ในงานที่ไม่มี attention คือเวกเตอร์สรุปตัวเดียวที่ encoder ส่งให้ decoder ส่วนในงานที่มี attention คือผลรวมถ่วงน้ำหนักของโน้ตฝั่ง encoder ที่คำนวณใหม่ในแต่ละก้าว (context ของก้าวนี้) บท 2.4
context window
จำนวน token สูงสุดที่โมเดลรับได้ในครั้งเดียว ภาษาที่ใช้ token มากจึงใส่ข้อความได้สั้นกว่า บท 1.2
contextual embedding
embedding ที่คำนวณใหม่จากทั้งประโยค คำเดียวกันในคนละประโยคจึงได้เวกเตอร์ต่างกัน บท 2.1
continued pretraining (การฝึกล่วงหน้าต่อ)
เอาโมเดลที่ pretrain แล้วมาฝึกเกมเดิมต่อด้วยข้อมูลใหม่ เช่นภาษาไทย บางครั้งเพิ่มชิ้นคำเข้าคลังด้วย บท 3.3
convex combination (fusion)
ผสมคะแนนที่ normalize แล้วด้วยน้ำหนัก a กับ 1 − a ต้องเลือก a จากชุดข้อมูลที่ไม่ใช่ชุดทดสอบ บท 6.2
coreference resolution (การหาคำที่อ้างถึงสิ่งเดียวกัน)
การหาว่าคำสรรพนามหรือคำเรียกซ้ำในข้อความชี้กลับไปที่สิ่งใด สำคัญกับการหั่นเอกสาร เพราะชิ้นที่ถูกตัดออกจากบริบทจะไม่เหลือตัวอ้างอิง โดยเฉพาะภาษาไทยที่ละประธานได้อิสระ บท 4.4
cosine similarity
dot product หารด้วยความยาวของทั้งสองเวกเตอร์ วัดแค่มุม ได้ 1 เมื่อชี้ทางเดียวกัน 0 เมื่อตั้งฉาก −1 เมื่อชี้สวนกัน บท 2.2
counterfactual pair (คู่ประโยคสลับคุณสมบัติ)
ข้อความสองชุดที่เหมือนกันทุกตัวอักษรยกเว้นคุณสมบัติเดียว (เช่น ครับ/ค่ะ) ใช้ดูว่าคำตอบเปลี่ยนตามคุณสมบัตินั้นหรือไม่ บท 5.3
CRF (conditional random field)
โมเดลที่ให้คะแนนทั้งลำดับป้ายของประโยค จากลักษณะของคำและคะแนนการเปลี่ยนจากป้ายหนึ่งไปอีกป้าย แล้วเลือกลำดับที่คะแนนรวมสูงสุด บท 5.4
cross-encoder
ป้อนคำค้นกับเอกสารคู่กันเข้า encoder ตัวเดียวแล้วออกคะแนน มักแม่นกว่าแต่ต้องรันใหม่ทุกคู่ จึงใช้แค่เรียงผลรอบแรกใหม่ บท 4.1
cross-entropy
loss ที่ใส่ −ln ให้ความน่าจะเป็นที่โมเดลให้กับคำตอบที่ถูก ถ้าให้เต็ม 1 ได้ 0 ยิ่งให้น้อยยิ่งสูง บท 2.3
custom dictionary (พจนานุกรมเสริม)
รายการคำที่เราเพิ่มให้ตัวตัดคำเอง เช่นชื่อเมนูหรือชื่อสถานที่ใหม่ที่พจนานุกรมมาตรฐานยังไม่มี บท 1.1
data contamination (ข้อสอบรั่ว)
เมื่อข้อมูลทดสอบหลุดเข้าไปอยู่ในข้อมูลฝึก คะแนนจึงวัดความจำมากกว่าความสามารถ บท 3.7
decoder-only
โมเดลที่แต่ละชิ้นเห็นแค่ชิ้นก่อนหน้า ทายชิ้นถัดไปได้จึงเขียนข้อความต่อได้ เป็นฐานของแชตบอต บท 3.3
decoding (การเลือก token)
ขั้นที่เลือกชิ้นคำหนึ่งชิ้นจากตารางความน่าจะเป็นที่โมเดลให้ แล้วต่อท้ายข้อความก่อนทายรอบถัดไป บท 3.4
distinct-n
สัดส่วนกลุ่มคำยาว n ที่ไม่ซ้ำกันในชุดข้อความ ใช้วัดความหลากหลายของข้อความที่โมเดลสร้าง บท 3.4
distributional hypothesis (สมมติฐานการกระจายของคำ)
คำที่อยู่ในบริบทคล้ายกันมักมีความหมายคล้ายกัน รู้จักคำได้จากคำรอบข้างของมัน บท 2.1
document expansion (doc2query)
ให้โมเดลเขียนคำถามที่เอกสารแต่ละชิ้นน่าจะตอบได้ แล้วต่อท้ายเอกสารก่อนทำดัชนี BM25 คำใหม่จึงตรงกับคำถามจริงได้โดยไม่ต้องเปลี่ยนตอนค้น บท 6.5
document frequency (df)
จำนวนเอกสารในกองที่มีคำหนึ่งอยู่ บท 1.5
DOS RAG (Document's Original Structure RAG)
RAG ที่ดึง passage ตามคะแนนเหมือนเดิม แต่เรียงชุดที่ดึงได้ใหม่ตามตำแหน่งในเอกสารก่อนส่งให้ reader dos-rag
dot product (ผลคูณจุด)
คูณช่องที่ตรงกันของสองเวกเตอร์แล้วบวกทุกช่อง เท่ากับความยาวเงาของเวกเตอร์หนึ่งบนอีกเวกเตอร์คูณความยาวของเวกเตอร์นั้น เรียกอีกชื่อว่า inner product บท 2.2
DPO
Direct Preference Optimization: ฝึกจากคู่ความชอบตรง ๆ ด้วย loss แบบ logistic บน margin ไม่ต้องมี reward model แยก บท 3.6
DPO margin
β × [(log π − log π_ref) ของคำตอบ chosen − (log π − log π_ref) ของคำตอบ rejected] บวกแปลว่าโมเดลเอียงไปทางคำตอบที่คนเลือกเทียบกับตอนเริ่ม บท 3.6
dropout
การสุ่มปิดนิวรอนบางตัวระหว่างฝึก เพื่อลด overfitting บท 2.3
DSI (Differentiable Search Index)
retriever ที่ให้โมเดลภาษาจำ id ของเอกสารไว้ในน้ำหนักของตัวเอง แล้วรับคำถามเข้าไปและสร้าง id ออกมาตรง ๆ โดยไม่ต้องมี index แยก stair
edit distance (ระยะแก้ไข)
จำนวนครั้งที่ต้องแทรก ลบ หรือแทนที่ เพื่อเปลี่ยนข้อความหนึ่งเป็นอีกข้อความหนึ่ง ค่าขึ้นกับหน่วยที่นับ: code point กับก้อนที่ตาเห็นให้คำตอบต่างกัน แบบที่เพิ่มการสลับตัวติดกันเรียก Damerau-Levenshtein บท 1.1
embedding (dense vector)
เวกเตอร์สั้นหลักสิบถึงหลักพันช่อง ช่องเกือบทุกช่องไม่เป็น 0 และไม่มีชื่อ ใช้แทนคำหรือข้อความให้โมเดลคำนวณ บท 2.1
encoder-decoder (seq2seq)
โมเดลสองส่วน encoder อ่านลำดับต้นทาง decoder เขียนลำดับปลายทางทีละชิ้นโดยมีต้นทางเป็นเงื่อนไข ความยาวสองฝั่งไม่ต้องเท่ากัน บท 2.4
encoder-only
โมเดลที่ทุกชิ้นเห็นทั้งประโยค (ไม่มี causal mask) เหมาะกับจัดหมวดและทำเวกเตอร์ แต่เขียนข้อความต่อเองไม่ได้ บท 3.3
entity-level F1 (F1 ระดับ entity)
F1 ที่นับหนึ่งชื่อเป็นหนึ่งคำตอบ ชื่อนับว่าถูกเมื่อประเภทและขอบทั้งสองข้างตรงกับเฉลย ขอบผิดนับเป็นผิดสองครั้ง (ทายเกินหนึ่ง พลาดหนึ่ง) บท 5.4
epoch (รอบ)
การฝึกผ่านข้อมูลฝึกครบหนึ่งรอบ บท 3.5
Euclidean distance (ระยะแบบยุคลิด)
ระยะเส้นตรงระหว่างปลายเวกเตอร์สองอัน ยิ่งน้อยยิ่งใกล้ ถ้า normalise ก่อนจะเรียงลำดับเหมือน cosine บท 2.2
evidence recall@B
สัดส่วนของข้อความหลักฐานที่อยู่ใน B token แรกที่ reader จะได้อ่าน ใช้เทียบ retriever ที่หั่นเอกสารต่างกันในงบเดียวกัน raptor
exact match (EM)
ได้ 1 เมื่อคำตอบตรงกับคำตอบมาตรฐานทุกตัวอักษรหลัง normalize ไม่งั้นได้ 0 บท 4.4
extrinsic hallucination (การแต่งที่ตรวจจากต้นทางไม่ได้)
คำตอบที่เอกสารต้นทางไม่ยืนยันและไม่แย้ง อาจจริงหรือไม่จริงก็ได้ แต่ระบบไม่มีหลักฐาน บท 5.3
F1
ค่าเฉลี่ยฮาร์มอนิกของ precision และ recall ถ้าตัวใดต่ำ F1 ก็ต่ำตาม บท 1.4
false negative (ตัวหลอกปลอม)
ข้อความที่ถูกนับเป็นตัวหลอกทั้งที่จริง ๆ เป็นคำตอบ เช่นย่อหน้าจากบทความเดียวกันใน batch ทำให้ loss ลงโทษคำตอบที่ถูก บท 4.2
feed-forward
โครงข่ายที่ข้อมูลไหลทางเดียวจากข้อมูลเข้าไปปลายทาง ไม่วนกลับ บท 2.3
feed-forward network (FFN)
โครงข่ายสองชั้นในบล็อก transformer ที่ใช้น้ำหนักชุดเดียวกันกับทุกตำแหน่งแยกกัน ไม่ผสมข้อมูลข้ามคำ บท 3.2
feed-forward neural language model
โมเดลภาษาของ Bengio et al. (2003) ที่ต่อเวกเตอร์ของ n−1 คำก่อนหน้า ผ่านชั้นซ่อน แล้วให้คะแนนทุกคำในคลังศัพท์ด้วย softmax บท 2.3
fertility
จำนวน token เฉลี่ยต่อหนึ่งคำ ยิ่งน้อยยิ่งประหยัด สำหรับภาษาไทยต้องบอกด้วยว่าใช้ตัวตัดคำอะไรนับคำ บท 1.2
few-shot
สั่งงานพร้อมแนบตัวอย่างโจทย์และคำตอบสองสามข้อไว้ใน prompt บท 3.4
fine-tuning (การปรับจูนโมเดล)
ฝึกโมเดลที่ pretrain แล้วต่อด้วยข้อมูลที่มีป้ายของงานเรา ด้วย learning rate เล็กและไม่กี่รอบ บท 3.5
first-stage retrieval (การค้นขั้นแรก)
ขั้นที่คัดผู้สมัครจากทั้งคลังด้วยวิธีราคาถูกที่คำนวณฝั่งเอกสารไว้ล่วงหน้าได้ เช่น BM25 หรือ bi-encoder ชิ้นที่หลุดจากขั้นนี้ ขั้นหลังจะไม่มีทางเห็นอีก บท 6.1
FLOPS regulariser
ตัวลงโทษของ SPLADE ที่กดน้ำหนักของคำซึ่งไม่เป็นศูนย์บ่อยในทั้ง batch เวกเตอร์จึงบางลงและค้นใน inverted index ได้เร็วขึ้น ค่า λ ยิ่งสูงเวกเตอร์ยิ่งบาง แลกกับคุณภาพที่ลดลง splade
forward pass
การส่งข้อมูลผ่านโครงข่ายจากชั้นแรกไปถึงปลายทางเพื่อได้คำตอบ บท 2.3
frozen encoder (linear probe) (เวกเตอร์แช่แข็ง)
ใช้ encoder โดยไม่ปรับน้ำหนักเลย แล้วฝึกแค่ตัวจำแนกเล็ก ๆ (เช่น logistic regression) บนเวกเตอร์ที่ได้ เพื่อดูว่าเวกเตอร์มีข้อมูลอะไรอยู่ บท 4.1
full fine-tuning
fine-tuning ที่ปรับพารามิเตอร์ทุกตัวของโมเดล ต้องเก็บ gradient และค่าของ optimizer ของทุกตัว และได้โมเดลขนาดเท่าเดิมหนึ่งชุดต่องาน บท 3.5
gate (ประตู)
ตัวเลขระหว่าง 0 ถึง 1 ที่โมเดลเรียนเอง ใช้คูณเพื่อเลือกว่าจะเก็บ ลบ หรือเพิ่มข้อมูลในโน้ตแค่ไหน บท 2.4
gold
เอกสารหรือท่อนที่มีป้ายว่าเป็นคำตอบของคำถาม บท 4.3
gradient
ความชันของ loss เทียบกับ weight แต่ละตัว เป็นบวกแปลว่าเพิ่ม weight แล้ว loss เพิ่ม บท 2.3
gradient descent
ขยับ weight สวนทาง gradient ทีละก้าว เพื่อให้ loss ลดลง บท 2.3
grapheme
สิ่งที่คนมองว่าเป็นหนึ่งตัวอักษรบนจอ ตามกฎของ Unicode (UAX #29) สระบนและวรรณยุกต์ติดไปกับพยัญชนะ แต่สระหน้าอย่าง เ เป็นหน่วยของตัวเอง บท 1.1
greedy search (ค้นหาแบบละโมบ)
วิธีเลือกคำตอนสร้างข้อความที่หยิบคำคะแนนสูงสุดทีละก้าว เร็วแต่ถ้าพลาดตอนต้นจะพาพลาดทั้งประโยค บท 2.4
GRPO
ให้โมเดลตอบคำถามเดียวหลายครั้ง แล้วใช้รางวัลของแต่ละคำตอบลบค่าเฉลี่ยของกลุ่มเป็นน้ำหนักขยับ ไม่ต้องมี reward model บท 3.6
GRU
RNN แบบมีประตูที่ได้แรงบันดาลใจจาก LSTM แต่จัดวางประตูต่างออกไป บท 2.4
guardrail (ตัวกันราง)
การตรวจแบบตายตัวที่ครอบรอบการสร้างข้อความของโมเดล ทั้งขาเข้าและขาออก เช่น regex ที่ลบเลขบัตรออกจากคำตอบ บท 5.3
hallucination (การแต่งคำตอบ)
คำตอบที่ฟังดูมีเหตุผลแต่ไม่ตรงกับความจริง และโมเดลมักพูดด้วยความมั่นใจเท่ากับตอนตอบถูก บท 4.4
hard negative (ตัวหลอกยาก)
ตัวหลอกที่หน้าตาคล้ายคำตอบแต่ไม่ใช่ เช่นข้อความที่ BM25 ให้คะแนนสูงแต่ไม่มีคำตอบ ใน DPR ให้ผลดีกว่าตัวหลอกสุ่ม (ในการฝึกเล็ก ๆ ของบท 4.2 แยกไม่ออก) บท 4.2
hidden layer (ชั้นซ่อน)
ชั้นของนิวรอนที่อยู่ระหว่างข้อมูลเข้ากับปลายทาง สร้างสัญญาณใหม่จากข้อมูลเข้าหลายตัวรวมกัน บท 2.3
hidden state
เวกเตอร์ที่ RNN อัปเดตทุกครั้งที่อ่านคำหนึ่งคำ ทำหน้าที่เป็นโน้ตสรุปสิ่งที่อ่านมาแล้ว บท 2.4
hit@k (top-k accuracy)
ได้ 1 ถ้ามี gold อย่างน้อยหนึ่งชิ้นใน k อันดับแรก ไม่อย่างนั้นได้ 0 เท่ากับ recall@k เมื่อคำถามมี gold ชิ้นเดียว บท 4.3
HNSW (Hierarchical Navigable Small World)
ดัชนีแบบกราฟหลายชั้น ชั้นบนมีจุดน้อยให้กระโดดไกล ชั้นล่างมีครบให้ค้นละเอียด ค้นด้วยการเดินไปหาเพื่อนบ้านที่ใกล้คำถามขึ้นเรื่อย ๆ ปรับความละเอียดตอนค้นด้วย efSearch บท 6.4
hybrid retrieval (การค้นแบบผสม)
รวมผลของระบบค้นหลายแบบ เช่น BM25 กับ dense เข้าเป็นรายการเดียว เพราะแต่ละแบบพลาดคนละคำถาม บท 6.2
HyDE (hypothetical document embeddings)
ให้ LLM เขียนคำตอบสมมติของคำถาม แล้วใช้เวกเตอร์ของคำตอบสมมติ (เฉลี่ยกับเวกเตอร์ของคำถาม) ไปค้นแทนเวกเตอร์ของคำถามอย่างเดียว บท 6.5
IDF (inverse document frequency)
น้ำหนักความหายากของคำ df ยิ่งน้อย IDF ยิ่งสูง บท 1.5
implicit reward (รางวัลแฝง)
β × log(π/π_ref) ของคำตอบหนึ่ง คะแนนที่ DPO สร้างขึ้นโดยไม่มี reward model บท 3.6
in-batch negatives (ตัวหลอกในกลุ่ม)
ใช้คำตอบของคำถามอื่นใน batch เดียวกันเป็นตัวหลอก batch ละ B ข้อได้ตัวหลอก B−1 ชิ้นต่อคำถามโดยไม่ต้องหาเพิ่ม บท 4.2
in-context learning (การเรียนรู้ในคำสั่ง)
การที่ตัวอย่างใน prompt ช่วยให้โมเดลทำงานได้ โดยไม่มีน้ำหนักตัวไหนในโมเดลเปลี่ยน บท 3.4
independent cropping (การตัดสองช่วง)
วิธีสร้างคู่ฝึกของ Contriever: สุ่มตัดสองช่วงจากเอกสารเดียวกันแยกกัน แล้วถือว่าทั้งสองช่วงเป็นคู่ที่ควรอยู่ใกล้กัน บท 6.7
indirect prompt injection (คำสั่งแฝงทางอ้อม)
คำสั่งที่ซ่อนอยู่ในข้อมูลที่ระบบดึงเข้ามา เช่น ย่อหน้าที่ค้นได้ แล้วโมเดลทำตามราวกับเป็นคำสั่งของผู้ใช้ บท 5.1
InfoNCE
loss ของการฝึกแบบจับคู่: softmax ของคะแนนความใกล้ข้ามคำตอบกับตัวหลอกทั้งหมด แล้วเอา −log ของความน่าจะเป็นที่ตกกับคำตอบ บท 4.2
instance
คำแต่ละครั้งที่ปรากฏในข้อความ นับซ้ำได้ (ตำราบางเล่มเรียกว่า token) บท 1.1
instruct model (โมเดลแชต)
โมเดลที่ฝึกต่อจาก base model ให้ตอบคำสั่งแบบผู้ช่วย (รายละเอียดในบท 3.6) บท 3.4
inter-annotator agreement (ความสอดคล้องระหว่างผู้ติดป้าย)
สัดส่วนที่ผู้ติดป้ายตั้งแต่สองรายให้ป้ายตรงกันบนข้อมูลชุดเดียวกัน ใช้ตรวจว่ากติกาการติดป้ายชัดพอหรือยัง สถิติที่ใช้กันชื่อ Cohen κ และ Krippendorff α บท 4.3
interpolation
ผสมความน่าจะเป็นจาก bigram, unigram และส่วนเท่ากันทุกคำด้วยน้ำหนักที่เลือกบนชุด dev บท 1.3
intrinsic hallucination (การแต่งที่ขัดกับต้นทาง)
คำตอบที่ขัดกับเอกสารหรือข้อมูลที่ให้โมเดลไว้ เช่น เอกสารบอกสิบโมงแต่ตอบเก้าโมง บท 5.3
Inverse Cloze Task (ICT)
วิธีสร้างคู่ฝึกโดยไม่ต้องมีป้าย: หยิบประโยคหนึ่งจากข้อความมาเป็นคำถามแทน แล้วใช้ข้อความรอบ ๆ (ที่มักตัดประโยคนั้นออก) เป็นคำตอบ เสนอใน ORQA บท 6.7
inverted index (ดัชนีกลับด้าน)
โครงสร้างที่จดว่าแต่ละคำอยู่ในเอกสารไหน มีสองส่วนคือ dictionary และ postings เหมือนดัชนีท้ายเล่มของหนังสือ บท 1.5
IVF (inverted file index)
แบ่งเวกเตอร์ในคลังเป็น nlist กลุ่มด้วย k-means ตอนค้นเทียบแค่เวกเตอร์ใน nprobe กลุ่มที่จุดกลางใกล้คำถามที่สุด บท 6.4
Jaccard similarity
จำนวนคำที่มีร่วมกันหารด้วยจำนวนคำไม่ซ้ำทั้งหมดของสองข้อความ เห็นคำที่ซ้ำ แต่ไม่เห็นความหมาย บท 2.2
JSON schema (tool schema)
คำอธิบายเครื่องมือแบบมีโครงสร้าง บอกชื่อ หน้าที่ อาร์กิวเมนต์ ชนิดข้อมูล และช่องที่ต้องมี ใช้ทั้งบอกโมเดลและตรวจคำขอก่อนรัน บท 5.1
k-nearest neighbours (kNN) (เพื่อนบ้านใกล้สุด k ตัว)
ทายป้ายของข้อความใหม่จากป้ายของข้อความฝึก k ข้อความที่ใกล้ที่สุด (ในบทนี้วัดด้วย cosine) บท 4.1
Kendall τ
วัดว่าการเรียงลำดับสองชุดตรงกันแค่ไหน นับคู่ที่เรียงทางเดียวกันลบคู่ที่สลับกัน หารด้วยจำนวนคู่ทั้งหมด ได้ 1 เมื่อเหมือนกันทุกคู่ ใช้เทียบลำดับของระบบภายใต้ป้ายสองชุด บท 6.8
KL penalty (สายจูง KL)
โทษที่เพิ่มเมื่อ policy เขียนต่างจาก reference มากเกินไป กันไม่ให้หลุดไปหาช่องโหว่หรือลืมภาษา บท 3.6
knowledge citation (เลขอ้างอิง)
ให้โมเดลบอกว่าคำตอบมาจากเอกสารชิ้นไหน เช่น [2] เพื่อให้คนตรวจย้อนได้ บท 4.4
knowledge distillation (retrieval) (การกลั่นความรู้)
ให้โมเดลที่แม่นแต่ช้า (ครู เช่น cross-encoder) ให้คะแนนคู่ข้อมูล แล้วฝึกโมเดลที่เร็วกว่า (นักเรียน เช่น bi-encoder) ให้คะแนนตาม บท 6.6
L2 norm (ความยาวเวกเตอร์)
รากที่สองของผลบวกกำลังสองทุกช่อง เขียน ‖a‖ บท 2.2
L2 normalisation
หารทุกช่องของเวกเตอร์ด้วยความยาวของมันเอง ได้เวกเตอร์ยาว 1 ที่ชี้ทิศเดิม หลังจากนี้ dot product คือ cosine บท 2.2
language model (โมเดลภาษา)
โมเดลที่ให้ความน่าจะเป็นกับทุกคำที่อาจมาต่อจากข้อความข้างหน้า จึงให้คะแนนทั้งประโยคได้ บท 1.3
latent attention pooling
วิธีรวม hidden state ของทุก token เป็นเวกเตอร์เดียวของ NV-Embed ให้ทุก token attend กับ latent ที่ฝึกได้ ผ่าน MLP แล้วจึงเฉลี่ย แทนการใช้ token สุดท้ายหรือค่าเฉลี่ยตรง ๆ dpr-nv-embed
layer normalization (layer norm)
การปรับค่าในเวกเตอร์ของชิ้นคำหนึ่งตัวให้ค่าเฉลี่ย 0 ส่วนเบี่ยงเบนมาตรฐาน 1 แล้วปรับสเกลด้วยน้ำหนักที่เรียนได้ บท 3.2
learned sparse retrieval
retriever ที่ให้โมเดลทำนายน้ำหนักของทุกคำใน vocabulary แล้วเก็บเฉพาะช่องที่ไม่เป็นศูนย์ ใช้ inverted index แบบเดียวกับ BM25 ได้ แต่โมเดลเป็นคนเลือกน้ำหนักและเติมคำที่ไม่มีในข้อความได้ เช่น SPLADE splade
learning rate (อัตราการเรียนรู้)
ตัวคูณ gradient ในการขยับ weight ก้าวจริงยาว learning rate × gradient ถ้าใหญ่ไปจะก้าวข้ามจุดต่ำสุด เล็กไปจะเรียนช้า บท 2.3
learning to rank (การเรียนรู้การจัดอันดับ)
การเลิกจัดอันดับด้วยสูตรเดียว แล้วฝึกโมเดลจากหลายสัญญาณ (คะแนนจากตัวคำ ชื่อเรื่อง แหล่งที่มา ความใหม่) โดยใช้ป้ายจากพฤติกรรมผู้ใช้ เช่น การคลิก บท 1.5
lexical score
คะแนนการจับคู่แบบคำของ sparse head ใน BGE-M3 เอาน้ำหนักของ token ที่อยู่ทั้งในคำถามและเอกสารมาคูณกันแล้วบวกรวม token ที่ id ไม่ตรงกันไม่ได้คะแนน บท 1.2
likelihood
โอกาสเจอคำหนึ่งถ้าข้อความอยู่ในหมวดนั้น นับจากคำทั้งหมดของหมวดในข้อมูลฝึก บท 1.4
LLM-as-a-judge
ให้ LLM ตัดสินคุณภาพคำตอบ แบบให้คะแนนทีละคำตอบ (pointwise) หรือเลือกคำตอบที่ดีกว่าจากสองคำตอบ (pairwise) บท 3.7
LM head
ชั้นสุดท้ายที่แปลงเวกเตอร์เป็นคะแนนของทุกชิ้นคำในคลังศัพท์ แล้ว softmax เป็นความน่าจะเป็นของชิ้นคำถัดไป บท 3.2
logistic regression
ตัวจำแนกที่ให้น้ำหนักกับแต่ละ feature รวมกับ bias เป็นคะแนน z แล้วแปลงเป็นความน่าจะเป็นด้วย sigmoid หรือ softmax บท 1.4
logit (คะแนนดิบ)
คะแนนที่โมเดลให้แต่ละ token ก่อนแปลงเป็นความน่าจะเป็นด้วย softmax บท 3.4
longest matching
วิธีตัดคำด้วยพจนานุกรมที่คว้าคำยาวที่สุดจากซ้ายก่อนเสมอ เร็วแต่ตัดผิดได้ เช่น ตากผ้า|อ้อม บท 1.1
LoRA (low-rank adaptation)
แช่แข็งเมทริกซ์ W แล้วฝึกเมทริกซ์ผอม B (d×r) กับ A (r×d) ให้ผลลัพธ์เป็น Wx + BAx โดย B เริ่มที่ศูนย์ ฝึกเสร็จรวม BA กลับเข้า W ได้ บท 3.5
loss mask
การกำหนดว่าชิ้นไหนไม่ถูกคิด loss (มักใส่ label -100) ใน SFT ใช้ข้ามส่วนคำถามและ template บท 3.6
lost in the middle
ผลที่ LLM ใช้ข้อมูลตรงกลาง context ยาว ๆ ได้แย่กว่าข้อมูลที่อยู่ต้นหรือท้าย (Liu et al.) บท 4.4
LSTM
RNN ที่มีประตูสามบาน (forget, add, output) และโน้ตระยะยาวที่อัปเดตด้วยการบวก ทำให้จำข้อมูลได้นานกว่า RNN ธรรมดา บท 2.4
macro / micro average (retrieval)
macro คิดคะแนนทีละคำถามแล้วเฉลี่ย ทุกคำถามหนักเท่ากัน micro รวมจำนวนนับของทุกคำถามก่อนแล้วค่อยหาร บท 4.3
macro-F1
หา F1 ของแต่ละหมวดแล้วเฉลี่ยตรง ๆ ทุกหมวดมีน้ำหนักเท่ากัน บท 1.4
majority-class baseline (ตัวทายกลุ่มใหญ่สุด)
ตัวทายที่ตอบหมวดที่พบบ่อยที่สุดในข้อมูลฝึกทุกข้อ ใช้เป็นพื้นขั้นต่ำก่อนเชื่อตัวเลขของโมเดล บท 1.4
Margin-MSE
loss ของการกลั่นความรู้ที่ให้นักเรียนเลียน "ส่วนต่าง" ของคะแนนระหว่างเอกสารถูกกับตัวหลอก แทนคะแนนตรง ๆ เพราะครูกับนักเรียนให้คะแนนคนละสเกล บท 6.6
Markov assumption (สมมติฐานมาร์คอฟ)
การสมมติว่าคำถัดไปขึ้นกับคำก่อนหน้าแค่ไม่กี่คำ (bigram คือคำเดียว) เพื่อให้นับได้จริง บท 1.3
mask token (ชิ้นปิด)
ชิ้นพิเศษ ([MASK] หรือ <mask>) ที่ใส่แทนชิ้นที่ต้องการให้โมเดลทายใน MLM บท 3.3
masked language modeling (MLM)
เกมเติมชิ้นที่ถูกปิดโดยดูทั้งซ้ายและขวา ฝึกเฉพาะตำแหน่งที่ถูกเลือก ใช้ฝึก BERT บท 3.3
maximal matching
วิธีตัดคำด้วยพจนานุกรมที่ดูทุกวิธีที่พจนานุกรมรองรับ แล้วเลือกวิธีที่ได้จำนวนคำน้อยที่สุด newmm ของ PyThaiNLP ใช้วิธีนี้โดยไม่ตัดข้ามขอบ TCC บท 1.1
MaxSim
วิธีให้คะแนนของ late interaction: ชิ้นคำแต่ละชิ้นของคำถามหาชิ้นคำในเอกสารที่คล้ายที่สุด แล้วรวม (ColBERT) หรือเฉลี่ย (BGE-M3) ค่าความคล้ายเหล่านั้น บท 6.3
mean pooling
เฉลี่ยเวกเตอร์ของทุกชิ้นคำจริงในข้อความ (ไม่นับช่องเติม) ให้เป็นเวกเตอร์เดียว บท 4.1
merge
หนึ่งขั้นของ BPE ที่รวมสองชิ้นที่อยู่ติดกันเป็นชิ้นใหม่ บท 1.2
micro / macro STEDS
macro คือเฉลี่ยคะแนนของแต่ละเอกสาร ส่วน micro คือรวม edit distance ของทุกเอกสารแล้วหารด้วยผลรวมขนาด tree เอกสารใหญ่จึงมีน้ำหนักมากกว่าใน micro steds
micro-F1
รวม TP/FP/FN ของทุกหมวดเป็นตารางเดียวก่อนคิด ในงานที่ข้อความมีป้ายเดียว micro-F1 เท่ากับ accuracy บท 1.4
mini-batch
ข้อมูลกลุ่มเล็กที่ใช้หา gradient เฉลี่ยก่อนก้าวหนึ่งครั้ง บท 2.3
MLE (maximum likelihood estimation)
ประมาณความน่าจะเป็นด้วยการนับแล้วหาร เช่น จำนวนครั้งของ "กิน ส้มตำ" หารด้วยจำนวนครั้งของ "กิน" บท 1.3
MRR (mean reciprocal rank)
ค่าเฉลี่ยของ RR ข้ามทุกคำถาม บท 4.3
multi-head attention
การแบ่ง attention เป็นหลายหัว แต่ละหัวมีเมทริกซ์ query/key/value ของตัวเอง แล้วต่อผลเข้าด้วยกัน บท 3.2
multi-vector retrieval (late interaction)
เก็บเวกเตอร์ของทุกชิ้นคำในเอกสาร ตอนค้นให้แต่ละชิ้นของคำค้นหาชิ้นที่ใกล้สุดแล้วรวมคะแนน แบบ ColBERT อยู่ระหว่าง bi-encoder กับ cross-encoder บท 4.1
n-gram (เอ็นแกรม)
ลำดับหน่วยติดกัน n หน่วย และโมเดลที่ทายคำถัดไปจาก n−1 หน่วยก่อนหน้า บท 1.3
Naive Bayes
ตัวจำแนกที่คูณ prior ของหมวดกับโอกาสเจอแต่ละคำในหมวดนั้น โดยถือว่าแต่ละคำไม่เกี่ยวกัน แล้วเลือกหมวดที่ได้ผลคูณมากสุด บท 1.4
named entity recognition (NER) (การรู้จำชื่อเฉพาะ)
หาช่วงข้อความที่เป็นชื่อเฉพาะ เช่น คน สถานที่ องค์กร วันที่ แล้วบอกว่าเป็นประเภทไหน บท 5.4
nDCG@k
ให้คะแนน gain ของทุกอันดับหารด้วยค่าที่โตตามอันดับ (DCG) แล้วหารด้วยค่าของรายการในอุดมคติ (IDCG) รับป้ายหลายระดับได้ แต่ละแหล่งใช้สูตร gain และ discount ต่างกัน บท 4.3
negative (ตัวหลอก)
ข้อความที่ถูกนับว่าไม่ใช่คู่ของคำถามในข้อสอบนั้น loss ผลักมันออกห่าง บท 4.2
negative sampling
สุ่มคำมาจับคู่ปลอมกับคำกลางแล้วสอนให้โมเดลตอบว่าไม่ใช่เพื่อนบ้าน กันไม่ให้โมเดลตอบ "ใช่" ทุกข้อ บท 2.1
nested entity (ชื่อซ้อนชื่อ)
ชื่อเฉพาะที่มีชื่อเฉพาะอื่นอยู่ข้างใน เช่น ตำแหน่งที่มีชื่อองค์กรและวันที่ซ้อน ป้าย BIO ชั้นเดียวแทนไม่ได้ บท 5.4
neural network (โครงข่ายประสาท)
นิวรอนหลายตัวต่อกันเป็นชั้น ผลของชั้นหนึ่งเป็นข้อมูลเข้าของชั้นถัดไป บท 2.3
neuron (นิวรอน)
หน่วยคำนวณที่คูณข้อมูลเข้าด้วย weight บวก bias แล้วส่งผ่านฟังก์ชันหักงอ เช่น sigmoid หรือ ReLU ตัวจัดหมวดของบท 1.4 คือนิวรอนหนึ่งตัว บท 2.3
next sentence prediction (NSP)
เกมฝึกของ BERT รุ่นแรกที่ให้ทายว่าสองประโยคต่อกันจริงไหม โดยอ่านจากเวกเตอร์ [CLS] RoBERTa และ XLM-R ตัดเกมนี้ออก บท 4.1
no_repeat_ngram_size
ค่าตั้งที่ห้ามลำดับ token ยาว n ที่เคยเกิดแล้วเกิดซ้ำ ภาษาไทยที่คำหนึ่งกินหลาย token อาจถูกบังคับให้สะกดผิด บท 3.4
noisy channel (ช่องสัญญาณมีสัญญาณรบกวน)
กรอบคิดว่าสิ่งที่เห็น (คำที่สะกดผิด เสียงที่ฟังไม่ชัด) คือของที่ถูกซึ่งถูกรบกวนระหว่างทาง แล้วเลือกคำที่ให้ค่า P(x|w)·P(w) สูงสุด โดย P(w) คือ language model บท 1.3
normalization
การแปลงข้อความที่เขียนได้หลายแบบให้เป็นแบบเดียวก่อนเปรียบเทียบ เช่น NFC และ NFKC ของ Unicode หรือ pythainlp.util.normalize ซึ่งมีกฎเฉพาะภาษาไทย บท 1.1
observation (ผลที่สังเกตได้)
ข้อความที่ส่งกลับให้โมเดลหลังรันเครื่องมือ เช่น ผลค้น ผลคำนวณ หรือข้อความ error บท 5.1
offset mapping
ตำแหน่งเริ่มและจบของแต่ละ token ในข้อความต้นฉบับ ใช้ไฮไลต์คำได้แม้ข้อความที่ถอดกลับจะไม่ตรงต้นฉบับ บท 1.2
one-hot vector
เวกเตอร์ยาวเท่าคลังศัพท์ ทุกช่องเป็น 0 ยกเว้นช่องของคำนั้นเป็น 1 ทุกคู่คำที่ต่างกันมี dot product เป็น 0 จึงบอกความคล้ายไม่ได้ บท 2.1
OOV (out-of-vocabulary)
หน่วยในข้อความทดสอบที่ไม่เคยพบในข้อมูลที่ใช้นับ บท 1.3
oracle (retrieval)
เงื่อนไขทดลองที่ส่งเอกสารที่มีคำตอบแน่ ๆ ให้โมเดล ใช้ดูว่าถ้าค้นได้สมบูรณ์แบบ ระบบจะดีขึ้นแค่ไหน บท 4.4
overfitting
อาการที่ loss บนข้อมูลฝึกลดต่อ แต่ loss บนข้อมูลที่แยกไว้กลับเพิ่ม โมเดลจำข้อมูลฝึกแทนที่จะเรียนรูปแบบทั่วไป บท 2.3
overthinking (คิดเกินจำเป็น)
โมเดลเขียนความคิดยาวมากกับโจทย์ง่าย เสียต้นทุนโดยไม่แม่นขึ้น บท 5.2
padding (ช่องเติม)
ชิ้น <pad> ที่เติมท้ายข้อความสั้นให้ยาวเท่าข้อความยาวสุดในชุด เพื่อให้ป้อนเป็นกล่องสี่เหลี่ยมได้ บท 4.1
page navigator
ขั้นแรกของ DocLens ที่ให้ LLM อ่านทุกหน้าของเอกสารพร้อมคำถาม แล้วชี้เลขหน้าที่มีหลักฐาน สุ่มหลายรอบแล้วรวมผลเพื่อเน้น recall doclens
paired bootstrap
สุ่มหยิบรายการทดสอบแบบใส่คืนหลายรอบ ใช้รายการชุดเดียวกันกับทั้งสองระบบ แล้วดูการกระจายของผลต่างคะแนน บท 3.7
parameter (พารามิเตอร์)
ตัวเลขที่โมเดลเรียนจากการฝึก เช่นค่าในตาราง embedding และในเมทริกซ์ของแต่ละบล็อก บท 3.2
PEFT (parameter-efficient fine-tuning)
ตระกูลวิธีที่แช่แข็งโมเดลเกือบทั้งหมดแล้วฝึกแค่ส่วนน้อย เช่น LoRA บท 3.5
perplexity
ค่าที่บอกว่าโมเดล "แปลกใจ" กับข้อความทดสอบแค่ไหน ยิ่งต่ำยิ่งดี เทียบกันได้เฉพาะเมื่อคลังศัพท์เหมือนกัน บท 1.3
PII (ข้อมูลที่ระบุตัวบุคคลได้)
ข้อมูลที่ชี้ไปถึงคนคนหนึ่งได้ เช่น ชื่อ เลขบัตรประชาชน เบอร์โทร บท 5.3
pointwise / listwise (ranking)
pointwise ให้คะแนนทีละคู่ (คำถาม, เอกสาร) โดยไม่ดูเอกสารอื่น แล้วเรียงตามคะแนน listwise ให้โมเดลเห็นหลายเอกสารพร้อมกันแล้วตอบออกมาเป็นลำดับ เช่น RankGPT บท 6.1
policy
โมเดลที่กำลังถูกฝึกใน RLHF หรือ DPO บท 3.6
Poly-encoder
สถาปัตยกรรมระหว่าง bi-encoder กับ cross-encoder: เวกเตอร์เอกสารยังเก็บล่วงหน้าได้ แต่ฝั่งคำถามมีหลายเวกเตอร์ให้เอกสาร attend อีกชั้นหนึ่งก่อนคิด dot product บท 6.1
pooling (การรวบเวกเตอร์)
ย่อเวกเตอร์หนึ่งอันต่อชิ้นคำให้เหลือเวกเตอร์เดียวต่อข้อความ เช่น หยิบชิ้นแรก ([CLS]) หรือเฉลี่ยทุกชิ้น (mean pooling) บท 4.1
pooling (relevance judgments)
ให้คนตัดสินเฉพาะเอกสารที่ระบบชุดหนึ่งเคยหาเจอ เอกสารดีที่ไม่เคยอยู่ใน pool จะไม่มีป้ายและถูกนับว่าไม่เกี่ยว บท 4.3
position bias (ความลำเอียงเรื่องตำแหน่ง)
เมื่อกรรมการเลือกตามตำแหน่งของคำตอบ (เช่น ช่อง A) มากกว่าเนื้อหา ตรวจได้โดยตัดสินซ้ำหลังสลับลำดับ บท 3.7
positional embedding (เวกเตอร์ตำแหน่ง)
เวกเตอร์ที่บวกเข้ากับ embedding ของชิ้นคำเพื่อบอกลำดับ เพราะ attention เองไม่รู้ว่าคำไหนมาก่อน บท 3.1
positional index
inverted index ที่เก็บตำแหน่งของคำด้วย ทำให้ค้นวลีที่คำต้องอยู่ติดกันได้ บท 1.5
positive pair (คู่ที่ถูก)
ข้อความสองชิ้นที่ข้อมูลฝึกบอกว่าควรอยู่ใกล้กัน เช่นคำถามกับย่อหน้าที่มีคำตอบ บท 4.2
post-training (การฝึกหลังขั้นฝึกล่วงหน้า)
ทุกขั้นที่ฝึกต่อจาก base model เพื่อให้เป็นผู้ช่วย เช่น SFT, RLHF, DPO บท 3.6
postings
รายการเอกสารที่มีคำหนึ่ง ๆ มักเก็บจำนวนครั้ง (tf) และบางระบบเก็บตำแหน่งด้วย บท 1.5
PPMI (positive pointwise mutual information)
น้ำหนักที่ถามว่าสองคำอยู่ด้วยกันบ่อยกว่าที่ควรบังเอิญแค่ไหน ค่าลบตัดเป็น 0 บท 2.1
PPO
วิธีขยับ policy แบบ reinforcement learning ที่ InstructGPT ใช้ ต้องมีหลายโมเดลในหน่วยความจำ บท 3.6
pre-tokenization
ขั้นที่แบ่งข้อความเป็นก้อนใหญ่ก่อนเลือกชิ้น ขั้นถัดไปรวมชิ้นข้ามขอบก้อนไม่ได้ regex ที่แบ่งตามตัวอักษรตัดภาษาไทยตรงวรรณยุกต์และสระบนล่าง บท 1.2
precision
ในข้อที่โมเดลบอกว่าเป็นหมวดนี้ มีสัดส่วนเท่าไรที่เป็นหมวดนี้จริง บท 1.4
precision@k
สัดส่วนของ k อันดับแรกที่เป็น gold ถ้ามี gold ท่อนเดียว precision@10 ได้สูงสุดแค่ 0.1 บท 4.3
preference data (ข้อมูลความชอบ)
คู่คำตอบของคำถามเดียวกันที่คนบอกว่าอันไหนดีกว่า บท 3.6
pretraining (การฝึกล่วงหน้า)
ขั้นฝึกโมเดลกับข้อความดิบจำนวนมากครั้งเดียว ก่อนเอาไปฝึกต่อหรือใช้กับงานเฉพาะ บท 3.3
prior
โอกาสของหมวดก่อนเห็นข้อความ นับจากสัดส่วนของหมวดในข้อมูลฝึก บท 1.4
product quantization (PQ)
หั่นเวกเตอร์เป็นหลายท่อนย่อย แต่ละท่อนแทนด้วยเลขของจุดกลางที่ใกล้ที่สุด (เช่น 1 ไบต์ต่อท่อน) ทำให้เวกเตอร์เหลือไม่กี่สิบไบต์ แลกกับความคลาดเคลื่อนของระยะ บท 6.4
projection (การฉายเงา)
ส่วนของเวกเตอร์หนึ่งที่ทอดไปตามแนวของอีกเวกเตอร์ บท 2.2
prompt injection (คำสั่งแฝง)
คำสั่งที่แฝงมากับข้อมูลที่ระบบอ่าน เช่น เอกสารหรือเว็บ แล้วทำให้โมเดลทำตามแทนคำสั่งเดิม บท 5.3
pseudo-relevance feedback (PRF)
สมมติว่าเอกสารอันดับต้น ๆ ของการค้นรอบแรกเกี่ยวข้อง แล้วดึงคำเด่นจากเอกสารเหล่านั้นมาเติมในคำถามเพื่อค้นอีกรอบ RM3 เป็นสูตรที่นิยม บท 6.5
qrels (ป้ายความเกี่ยวข้อง)
รายการ (คำถาม, เอกสาร, ระดับความเกี่ยวข้อง) ที่ชุดทดสอบใช้ให้คะแนนระบบ เอกสารที่ไม่อยู่ในรายการถือว่าไม่เกี่ยว บท 6.8
query / key / value
ชื่อสามบทบาทใน attention ที่ยืมจากระบบค้นคืน query คือสิ่งที่ถามหา key คือสิ่งที่เอาไว้เทียบ value คือสิ่งที่หยิบกลับมา บท 2.4
query expansion (การขยายคำค้น)
การเติมคำพ้องหรือคำใกล้เคียงเข้าไปในคำค้นก่อนค้น เพื่อให้คำค้นตรงกับถ้อยคำที่เอกสารใช้จริง เป็นทางแก้ vocabulary mismatch ที่ยังทำงานบนตัวคำ บท 1.5
query/passage prefix (คำนำหน้า)
ข้อความสั้น ๆ ที่บางโมเดลต้องเติมหน้าคำค้นหรือเอกสาร เช่น "query: " เพราะถูกฝึกมาแบบนั้น บท 4.1
RAG (retrieval-augmented generation) (การสร้างคำตอบโดยค้นเอกสารก่อน)
ให้ LLM ค้นเอกสารที่เกี่ยวข้องก่อน แล้วใส่เอกสารนั้นลงใน prompt ให้โมเดลตอบจากสิ่งที่อ่าน แทนการตอบจากความจำในน้ำหนักล้วน ๆ บท 4.4
rank (LoRA)
ความกว้าง r ของเมทริกซ์ B และ A ใน LoRA ยิ่งเล็กยิ่งฝึกน้อย ต่อเมทริกซ์ d×d ใช้ 2dr ตัว บท 3.5
ranked list (รายการผลค้นหาที่เรียงแล้ว)
เอกสารหรือท่อนทั้งหมดที่ระบบให้คะแนนแล้วเรียงจากมากไปน้อย metric ของการค้นทุกตัวคิดจากลำดับนี้ บท 4.3
ReAct
รูปแบบเอเจนต์ที่สลับ "คิด" เป็นภาษากับ "ลงมือ" เรียกเครื่องมือ แล้วอ่าน observation ก่อนตัดสินใจขั้นต่อไป บท 5.1
reasoning model (โมเดลที่คิดก่อนตอบ)
โมเดลที่ถูกฝึก (มักด้วย RLVR) ให้เขียนความคิดยาว ๆ ก่อนตอบ เช่นในกล่อง <think> บท 5.2
recall
ในข้อที่เป็นหมวดนี้จริง โมเดลจับได้สัดส่วนเท่าไร บท 1.4
recall@k
จำนวน gold ใน k อันดับแรก หารด้วยจำนวน gold ทั้งหมด บางตำราใช้ชื่อนี้กับ hit@k ต้องดูนิยามก่อนเทียบ บท 4.3
reciprocal rank (RR)
1 หารด้วยอันดับของ gold ชิ้นแรก ไม่สนว่าหลังจากนั้นเป็นอะไร บท 4.3
reciprocal rank fusion (RRF)
ผสมหลายรายการด้วยอันดับอย่างเดียว คะแนนของเอกสารคือผลรวมของ 1/(k + อันดับ) จากทุกระบบ ไม่ต้อง normalize แต่มองไม่เห็นว่าแต่ละระบบมั่นใจแค่ไหน บท 6.2
reference (คำแปลอ้างอิง / คำตอบอ้างอิง)
ข้อความที่คนเขียนหรือแปลไว้เป็นเฉลย ใช้เทียบกับข้อความที่โมเดลเขียน บท 3.7
reference model (โมเดลอ้างอิง)
สำเนาของโมเดลตั้งต้นที่แช่แข็งไว้ ใช้เทียบว่า policy เปลี่ยนไปเท่าไร บท 3.6
relation extraction (การสกัดความสัมพันธ์)
ขั้นถัดจากการรู้จำเอนทิตี คือหาว่าเอนทิตีสองตัวในข้อความเกี่ยวข้องกันแบบใด แล้วเก็บผลเป็น knowledge graph บท 5.4
relevance label (ป้ายว่าเกี่ยว)
คำตัดสินล่วงหน้าว่าเอกสารไหนเกี่ยวกับคำถามไหน อาจเป็นแค่เกี่ยว/ไม่เกี่ยว หรือมีหลายระดับ เอกสารที่ไม่มีป้ายถูกนับว่าไม่เกี่ยว บท 4.3
ReLU
ฟังก์ชันที่ให้ค่าติดลบเป็นศูนย์และปล่อยค่าอื่นผ่าน ความชันเป็น 0 เมื่อค่าเข้าติดลบ จึงไม่ส่งความผิดย้อนผ่าน บท 2.3
repetition penalty
การลดคะแนนของ token ที่เคยออกมาแล้ว เพื่อลดการวนซ้ำ อาจทำให้หลุดภาษาหรือเนื้อหาเพี้ยน บท 3.4
representation-based vs interaction-based model
สองค่ายของแบบจำลองการค้นแบบ neural ก่อนยุค BERT: ค่ายแรกแปลงคำถามกับเอกสารเป็นเวกเตอร์แยกกันแล้ววัดความคล้าย (บรรพบุรุษของ bi-encoder) ค่ายที่สองเทียบคำของคำถามกับคำของเอกสารทีละคู่ (บรรพบุรุษของ cross-encoder และ ColBERT) แม่นกว่าแต่ช้ากว่า บท 6.9
representational harm (ความเสียหายเชิงภาพแทน)
เมื่อระบบวาดภาพคนกลุ่มหนึ่งผิด เหมารวม หรือทำให้หายไป เช่น เขียน "ผม" ให้ผู้ใช้ทุกคน บท 5.3
reranker (ตัวเรียงใหม่)
โมเดลที่อ่านคู่ (คำถาม, เอกสาร) ทีละคู่แล้วให้คะแนนใหม่ เพื่อเรียงผู้สมัครไม่กี่สิบชิ้นจากการค้นขั้นแรก มักเป็น cross-encoder บท 6.1
residual connection
การบวกเวกเตอร์ขาเข้ากลับเข้าไปกับผลของห้องย่อย ห้องย่อยจึงเพิ่มส่วนที่เปลี่ยนแทนการเขียนทับ บท 3.2
retrieval miss / reading miss (ค้นพลาด / อ่านพลาด)
ค้นพลาด: เอกสารที่มีคำตอบไม่อยู่ใน prompt · อ่านพลาด: เอกสารที่ถูกอยู่ใน prompt แล้วแต่โมเดลตอบผิด บท 4.4

โมเดลภาษาที่ค้นเอกสารมาใช้ระหว่างฝึกหรือระหว่างตอบ เช่น REALM ที่ฝึกตัวค้นไปพร้อมกับ pre-training, FiD ที่ให้ตัวสร้างข้อความอ่านหลายท่อนพร้อมกัน และ RETRO ที่ค้นจากคลังขนาดล้านล้าน token บท 6.9
retrieve-then-rerank (ค้นสองขั้น)
ท่อค้นที่ให้การค้นขั้นแรกคัด k ชิ้นจากทั้งคลัง แล้วให้ reranker เรียง k ชิ้นนั้นใหม่ เพดานของท่อคือ recall@k ของขั้นแรก บท 6.1
retriever / generator (reader) (ตัวค้น / ตัวสร้างคำตอบ (ตัวอ่าน))
สองส่วนของระบบ RAG ตัวค้นหาเอกสาร k ชิ้น ตัวสร้างคำตอบอ่านเอกสารนั้นแล้วตอบ บท 4.4
reward hacking (การโกงคะแนน)
โมเดลหาช่องโหว่ของตัวให้คะแนน ได้คะแนนสูงแต่ทำงานจริงแย่ลง บท 3.6
reward model (โมเดลให้คะแนน)
โมเดลที่อ่านคำถามกับคำตอบแล้วให้คะแนนตัวเลขตัวเดียว ฝึกจากคู่ความชอบ บท 3.6
RLHF (การเรียนแบบเสริมกำลังจากความเห็นมนุษย์)
ให้โมเดลเขียนคำตอบ ให้ reward model ให้คะแนน แล้วขยับโมเดลไปทางคะแนนสูง โดยมีสายจูง KL บท 3.6
RLVR
reinforcement learning with verifiable rewards: ให้รางวัลจากการตรวจคำตอบด้วยกฎ เช่นเลขคณิต บท 3.6
RNN (recurrent neural network)
โครงข่ายประสาทที่อ่านข้อมูลทีละชิ้นตามลำดับ แล้วส่งโน้ต (hidden state) ต่อให้ตัวเองในก้าวถัดไป โดยใช้น้ำหนักชุดเดียวกันทุกก้าว บท 2.4
ROUGE
metric งานสรุปความที่เน้น recall ของ n-gram (ROUGE-N) หรือลำดับย่อยร่วมที่ยาวที่สุด (ROUGE-L) ไลบรารี rouge_score แบบค่าเริ่มต้นลบอักษรไทยทิ้ง บท 3.7
round trip
การต่อชิ้นที่ตัดแล้วกลับเป็นข้อความ ถ้าได้ข้อความเดิมทุกตัวอักษรแปลว่าเครื่องมือตัดอย่างเดียว ไม่ได้แก้ข้อความ บท 1.1
round-trip consistency filtering (การกรองแบบย้อนหา)
เก็บคำถามสังเคราะห์ไว้เฉพาะเมื่อนำคำถามนั้นไปค้นแล้วเจอข้อความต้นทางในอันดับต้น ๆ (Promptagator ใช้ top-1) บท 6.7
sampling (การสุ่มตามความน่าจะเป็น)
เลือก token แบบทอยลูกเต๋าที่ถ่วงน้ำหนักตามความน่าจะเป็น ถามซ้ำจึงได้คำตอบไม่เหมือนเดิม บท 3.4
saturation (อิ่มตัว)
คำที่ซ้ำหลายครั้งได้คะแนนเพิ่มน้อยลงเรื่อย ๆ และไม่เกิน IDF ของคำนั้น บท 1.5
scaled dot-product attention
การให้คะแนน attention ด้วย dot product ของ query กับ key แล้วหารด้วย √d_k ก่อน softmax เพื่อไม่ให้ softmax คมเกินจนเรียนยาก บท 3.1
score normalization
ปรับคะแนนของแต่ละระบบให้อยู่สเกลเดียวกันก่อนผสม เช่น min-max (ลบค่าต่ำสุดแล้วหารด้วยช่วง), z-score หรือ theoretical min-max ที่ใช้ขอบล่างทางทฤษฎี (BM25 = 0, cosine = −1) บท 6.2
self-attention
attention ที่ทุกชิ้นคำในลำดับเดียวกันให้คะแนนและดึงข้อมูลจากทุกชิ้นคำ (รวมตัวเอง) ด้วย query, key และ value บท 3.1
self-consistency / majority vote (การโหวตเสียงข้างมาก)
ถามคำถามเดิมหลายรอบด้วยการสุ่ม แล้วเลือกคำตอบสุดท้ายที่ซ้ำมากที่สุด ต้องมีวิธีตัดสินว่าคำตอบสองแบบเท่ากัน บท 5.2
self-supervised learning (การเรียนแบบข้อมูลเฉลยตัวเอง)
ฝึกโมเดลโดยซ่อนบางส่วนของข้อความแล้วให้ทาย คำตอบมาจากข้อความเอง ไม่ต้องมีคนติดป้าย บท 3.3
semantic docid
รหัสเอกสารของ DSI ที่ได้จากการทำ k-means ซ้อนกันเป็นชั้นบน embedding ของเอกสาร รหัสคือเส้นทางในต้นไม้ของกลุ่ม เอกสารที่คล้ายกันจึงมีรหัสขึ้นต้นเหมือนกัน dsi
sentence segmentation (การตัดประโยค)
การหาจุดจบประโยค ภาษาไทยไม่มีจุดบอก และช่องว่างอาจเป็นจบประโยคหรือแค่เว้นจังหวะก็ได้ บท 1.1
SentencePiece
ไลบรารีที่ฝึกและใช้ tokenizer บนข้อความดิบ แทนช่องว่างด้วย ▁ รองรับทั้ง BPE และ Unigram ไม่ใช่ algorithm ในตัวเอง บท 1.2
sequence labeling (การติดป้ายตามลำดับ)
ให้ป้ายหนึ่งป้ายกับทุกหน่วยในข้อความ ผลลัพธ์ยาวเท่าข้อความที่ป้อน ป้ายของหน่วยหนึ่งขึ้นกับหน่วยข้าง ๆ บท 5.4
SGD (stochastic gradient descent)
gradient descent ที่ก้าวทีละ mini-batch แทนการรอครบทั้งชุด บท 2.3
sigmoid
ฟังก์ชันที่บีบตัวเลขใด ๆ ให้อยู่ระหว่าง 0 ถึง 1 ใช้แปลงคะแนนเป็นความน่าจะเป็นของหมวดบวกในงานสองหมวด บท 1.4
skip-gram
แบบหนึ่งของ word2vec ที่ทายคำรอบข้างจากคำกลาง (อีกแบบคือ CBOW ที่ทายคำกลางจากคำรอบข้าง) บท 2.1
softmax
ฟังก์ชันที่แปลงคะแนนของทุกหมวดเป็นความน่าจะเป็นที่รวมกันได้ 1 บท 1.4
span corruption
objective ของ T5: ปิดช่วงชิ้นที่ติดกันแทนด้วยป้ายช่อง แล้วให้ decoder เขียนเฉพาะช่วงที่หาย บท 3.3
sparse vector
เวกเตอร์ยาวที่ช่องเกือบทั้งหมดเป็น 0 เช่น แถวของตารางนับคำรอบข้าง บท 2.1
special token (token พิเศษ)
ชิ้นในคลังที่ไม่ใช่ข้อความ ใช้บอกโครงสร้าง เช่น เริ่มข้อความ ขึ้นบทบาทใหม่ หรือจบคำตอบ บท 3.4
static embedding
embedding แบบหนึ่งแถวต่อหนึ่งคำ ไม่ว่าคำนั้นอยู่ในประโยคไหน คำหลายความหมายจึงต้องแชร์แถวเดียว บท 2.1
STEDS (Semantic-TEDS)
TEDS ที่ HRDoc เสนอ โหนดสองตัวนับว่าตรงกันก็ต่อเมื่อ class และข้อความเหมือนกันทุกตัวอักษร ถ้าไม่ตรงก็เสียเต็ม 1 ใช้วัดสารบัญและ hierarchy เต็มของ Comp-HRDoc steds
stop words
คำที่เจอบ่อยจนแทบไม่ช่วยในการค้น เช่น ใน และ ระบบเก่ามักลบทิ้ง ระบบใหม่ปล่อยให้ IDF กดน้ำหนักเอง บท 1.5
stopping rule (กฎหยุด)
เงื่อนไขว่าเอเจนต์ควรเลิกวนเมื่อไร เช่น โมเดลตอบโดยไม่เรียกเครื่องมือ หรือครบจำนวนรอบสูงสุด หยุดเร็วไปได้คำตอบไม่ครบ ช้าไปเปลืองและพลาดสะสม บท 5.1
subword (ชิ้นคำ)
หน่วยที่อยู่ระหว่างคำกับตัวอักษร ชิ้นที่เจอบ่อยเก็บเป็นก้อนเดียว ชิ้นที่เจอน้อยประกอบจากก้อนเล็กกว่า บท 1.2
supervised fine-tuning (SFT) (การฝึกจากคู่คำสั่งคำตอบ)
ฝึกเกมทายชิ้นถัดไปต่อบนคู่คำสั่งกับคำตอบที่ดี โดยคิด loss เฉพาะส่วนคำตอบ บท 3.6
sycophancy (การตามใจผู้ใช้)
แนวโน้มที่โมเดลตอบสิ่งที่ผู้ใช้อยากได้ยินแทนสิ่งที่จริง บท 5.3
synthetic queries (คำถามสังเคราะห์)
คำถามที่ LLM เขียนให้ข้อความ (เช่น InPars, Promptagator) ใช้เป็นคู่ฝึกแทนคำถามที่คนเขียน บท 6.7
system prompt
ข้อความคำสั่งตั้งต้นที่ถูกวางไว้หน้าข้อความของผู้ใช้ทุกครั้ง ใช้กำหนดบทบาทและน้ำเสียงของผู้ช่วย บท 3.4
TCC (Thai Character Cluster)
กลุ่มตัวอักษรไทยที่ต้องอยู่ด้วยกันเสมอ บอกว่าตรงไหนห้ามตัด แต่ไม่ได้บอกว่าคำอยู่ตรงไหน บท 1.1
TEDS (Tree-Edit-Distance-based Similarity)
คะแนนความเหมือนของ tree สองต้น เท่ากับ 1 ลบ tree edit distance (insert, delete, rename) หารด้วยจำนวนโหนดของต้นที่ใหญ่กว่า ใช้ให้คะแนนสารบัญที่กู้มาเทียบกับของจริง longdocbench
TEDS-S
TEDS ที่ดูแค่โครงสร้าง ไม่สนข้อความในโหนดเลย มาจากงานวัดตาราง ในโพสต์นี้เรายืมมาใช้กับสารบัญด้วย steds
temperature (อุณหภูมิ)
ตัวเลขที่หารคะแนนก่อน softmax ค่าน้อยกว่า 1 ทำให้ตัวที่นำอยู่ยิ่งนำ ค่ามากกว่า 1 ทำให้ตารางแบนลง บท 3.4
temperature (contrastive)
ตัวหาร τ ของคะแนน cosine ก่อน softmax ใน InfoNCE ขยายช่องว่างของคะแนนที่ติดเพดาน −1 ถึง 1 เป็นหลักเดียวกับ temperature ตอนสุ่มคำในบท 3.4 บท 4.2
term frequency (tf)
จำนวนครั้งที่คำหนึ่งอยู่ในเอกสารหนึ่ง บท 1.5
term-document matrix
ตารางที่แถวคือคำ คอลัมน์คือเอกสาร ช่องคือจำนวนครั้ง ช่องส่วนใหญ่เป็นศูนย์ บท 1.5
test collection (ชุดทดสอบการค้น)
คลังเอกสาร ชุดคำถาม และป้ายบอกว่าเอกสารไหนเกี่ยวกับคำถามไหน (qrels) สามอย่างนี้รวมกันทำให้เทียบระบบค้นหลายระบบด้วยเกณฑ์เดียวกันได้ แนวทางนี้มาจากการทดลอง Cranfield บท 6.8
test-time compute (การคำนวณตอนตอบ)
แรงคำนวณที่จ่ายเพิ่มตอนใช้งานโมเดล เช่นให้คิดยาวขึ้นหรือถามหลายรอบ แทนการฝึกโมเดลให้ใหญ่ขึ้น บท 5.2
text classification (การจัดหมวดข้อความ)
งานที่รับข้อความหนึ่งก้อนแล้วตอบเป็นป้ายหนึ่งป้ายจากชุดที่กำหนดไว้ เช่น บวก กลาง ลบ หรือคำถาม บท 1.4
text span
ข้อความใต้หัวข้อหนึ่งใน tree ตั้งแต่หัวข้อนั้นไปจนถึงหัวข้อถัดไปที่ไม่ใช่ลูกหลานของมัน tree ที่ robust คือ tree ที่ text span ของทุกหัวข้อคลุมข้อความใต้หัวข้อนั้นใน tree จริงครบ shed
tf-idf
น้ำหนักคำที่ได้จากการคูณ tf กับ IDF บท 1.5
thinking budget (งบคิด)
จำนวน token สูงสุดที่ยอมให้โมเดลเขียนความคิด ถ้าเกินจะถูกตัดและอาจไม่มีคำตอบ บท 5.2
thinking mode (โหมดคิด)
สวิตช์ของโมเดลอย่าง Qwen3 (enable_thinking) ที่เปิดหรือปิดการเขียนความคิดก่อนตอบ บท 5.2
TOC tree (สารบัญแบบ tree)
โครงลำดับชั้นของหัวข้อในเอกสาร หัวข้อแต่ละตัวเป็นโหนด และหัวข้อย่อยเป็นลูกของหัวข้อที่ครอบมัน parser ส่วนใหญ่หาหัวข้อเจอ แต่กู้ความลึกได้ไม่ถูก longdocbench
token
ชิ้นข้อความที่โมเดลนับเป็นหนึ่งหน่วย อาจเป็นคำ ส่วนของคำ ตัวอักษร หรือแม้แต่ไบต์ที่ยังไม่ครบตัวอักษร บท 1.2
token classification
ต่อหัวจำแนกที่ทุกตำแหน่งของ encoder เพื่อทายป้ายทีละชิ้นคำ ถ้าคำถูกหั่นหลายชิ้น มักให้ป้ายเฉพาะชิ้นแรก บท 5.4
token F1
นับคำที่คำตอบกับคำตอบมาตรฐานมีร่วมกันแบบถุงคำ แล้วคิด F1 ภาษาไทยต้องตัดคำก่อน ผลจึงขึ้นกับตัวตัดคำ บท 4.4
token id
เลขประจำตัวของชิ้นหนึ่งในคลังชิ้นคำ และเป็นเลขแถวในตาราง embedding ของโมเดล บท 1.2
token premium
อัตราส่วนความยาว token ของประโยคเดียวกันในสองภาษา (Petrov et al. 2023) เช่นภาษาไทยเทียบภาษาอังกฤษ บท 1.2
tokenizer (ตัวหั่นข้อความ)
โปรแกรมที่แปลงข้อความเป็นลำดับ token id ให้โมเดล และแปลงกลับ มีสี่ขั้น: normalize, pre-tokenize, model, post-process บท 1.2
tokens per correct answer (token ต่อคำตอบที่ถูก)
จำนวน token ทั้งหมดที่จ่าย หารด้วยจำนวนคำตอบที่ถูก ใช้เทียบต้นทุนของแต่ละวิธี บท 5.2
tool calling (function calling) (การเรียกเครื่องมือ)
การที่โมเดลเขียนคำขอใช้เครื่องมือเป็น JSON ตาม schema ที่เรากำหนด แล้วโค้ดของเราเป็นฝ่ายรันเครื่องมือจริง บท 5.1
tool-selection accuracy
สัดส่วนงานที่เอเจนต์เลือกเครื่องมือตรงกับที่ควรใช้ บท 5.1
top-k sampling
ตัด token ทิ้งให้เหลือ k ตัวที่คะแนนสูงสุด แล้วแบ่งความน่าจะเป็นใหม่ก่อนสุ่ม บท 3.4
top-p sampling (nucleus sampling)
เก็บ token ชุดที่เล็กที่สุดที่ความน่าจะเป็นรวมถึง p แล้วสุ่มในชุดนั้น ขนาดชุดปรับตามความมั่นใจของโมเดล บท 3.4
trace (เส้นทางการทำงาน)
บันทึกทุกขั้นของเอเจนต์หนึ่งครั้ง ทั้งข้อความของโมเดล tool call และ observation ใช้ย้อนดูว่าพลาดตรงไหน บท 5.1
train / validation / test set (ชุดฝึก / ชุดตรวจ / ชุดทดสอบ)
สามกองของข้อมูล: ไว้เรียน (แบบฝึกหัด), ไว้เลือกค่าตั้ง (ข้อสอบจำลอง), และวัดครั้งเดียวตอนท้าย (ข้อสอบจริง) บท 1.4
transfer learning
เอาความรู้ที่โมเดลเรียนมาจากงานหนึ่งไปใช้ตั้งต้นกับอีกงาน จึงใช้ข้อมูลที่มีป้ายน้อยกว่าเริ่มจากศูนย์ บท 3.5
transformer
สถาปัตยกรรมโครงข่ายประสาทที่ส่งเวกเตอร์ของทุกชิ้นคำผ่านบล็อกซ้อนกันหลายชั้น แต่ละบล็อกมี self-attention กับ feed-forward ไม่ต้องอ่านทีละคำแบบ RNN บท 3.1
transition score (คะแนนการเปลี่ยนป้าย)
น้ำหนักใน CRF ของการที่ป้ายหนึ่งตามหลังอีกป้าย เช่น O → I-PERSON ได้คะแนนติดลบมาก ลำดับที่ผิดกติกา BIO จึงแทบไม่ถูกเลือก บท 5.4
type
คำไม่ซ้ำ ชุดของ type ทั้งหมดในข้อความคือคลังศัพท์ (vocabulary) บท 1.1
uniformity
ตัววัดว่าเวกเตอร์ทั้งหมดกระจายทั่วทรงกลมแค่ไหน (log ของค่าเฉลี่ย e^(−t·ระยะ²) ยิ่งต่ำยิ่งกระจาย 0 = ทุกเวกเตอร์ซ้อนกัน) บท 4.2
Unigram
วิธีเลือกชิ้นที่ให้คะแนนทุกวิธีตัดเป็นผลคูณความน่าจะเป็นของชิ้น แล้วเลือกวิธีที่คะแนนสูงสุด (Viterbi) คลังได้จากการตัดชิ้นที่ช่วยน้อยทิ้งทีละรอบ บท 1.2
unit vector (เวกเตอร์หนึ่งหน่วย)
เวกเตอร์ที่ยาว 1 ใช้เหมือนไม้บรรทัด: dot กับมันได้ความยาวเงาตรง ๆ บท 2.2
unjudged document (เอกสารที่ไม่มีใครตัดสิน)
เอกสารที่ระบบหาเจอแต่ไม่อยู่ใน qrels จึงถูกนับว่าไม่เกี่ยวโดยอัตโนมัติ ทั้งที่อาจเกี่ยวจริง ระบบที่ไม่ได้ช่วยสร้าง pool โดนผลนี้หนักที่สุด บท 6.8
UTF-8
วิธีเข้ารหัส code point เป็นไบต์ อักษรละตินใช้ 1 ไบต์ อักษรไทยใช้ 3 ไบต์ บท 1.1
vanishing gradients
ปัญหาที่สัญญาณสอนโมเดลถูกคูณด้วยค่าน้อยกว่าหนึ่งซ้ำ ๆ จนเกือบเป็นศูนย์ โมเดลจึงเรียนความสัมพันธ์ระยะไกลได้ยาก บท 2.4
verifier (ตัวตรวจคำตอบ)
โปรแกรมหรือโมเดลที่บอกว่าคำตอบถูกหรือผิด เช่นสคริปต์ที่แปลงเลขไทยแล้วเทียบกับเฉลย บท 5.2
vocabulary (คลังศัพท์)
ชุดของหน่วย (คำหรือชิ้นคำ) ที่ระบบรู้จัก ขนาดขึ้นกับตัวตัดคำและข้อมูลที่ใช้ บท 1.1
vocabulary mismatch
ปัญหาที่คำค้นกับเอกสารใช้คำต่างกันแต่ความหมายเดียวกัน การค้นจากคำจึงหาไม่เจอ บท 1.5
weight tying
การใช้ตาราง embedding ขาเข้าเป็นเมทริกซ์ของ LM head ด้วย ทำให้ไม่ต้องมีตารางขนาดคลังศัพท์สองชุด บท 3.2
weighted-F1
เฉลี่ย F1 ของแต่ละหมวดโดยถ่วงด้วยจำนวนข้อความของหมวด ไม่ใช่สิ่งเดียวกับ micro-F1 บท 1.4
whole-word masking (การปิดทั้งคำ)
ปิดทุกชิ้นของคำเดียวกันพร้อมกัน เพื่อไม่ให้ชิ้นที่เหลือเปิดโพย ภาษาไทยต้องตัดคำก่อนจึงจะทำได้ บท 3.3
window (co-occurrence) (หน้าต่างนับคำรอบข้าง)
ช่วงคำรอบคำกลางที่นับเป็นเพื่อนบ้าน เช่น ±2 คือไม่เกินสองคำทั้งซ้ายและขวา ในภาษาไทยขึ้นกับตัวตัดคำ (คนละเรื่องกับ context window ของโมเดลในบท 1.2) บท 2.1
word segmentation (การตัดคำ)
การหาขอบเขตของคำในข้อความที่ไม่เว้นวรรค ทำได้ทั้งแบบใช้พจนานุกรม (เช่น newmm, ICU) และแบบโมเดลที่เรียนจากคลังข้อความ (เช่น AttaCut) บท 1.1
word2vec
วิธีเรียน embedding ของคำ (Mikolov et al., 2013) โดยให้โมเดลทายเพื่อนบ้านของคำ แล้วเก็บตารางเวกเตอร์ที่ได้ไว้ใช้ บท 2.1
WordPiece
วิธีตัดของ BERT ที่หาชิ้นยาวที่สุดจากซ้ายในคลังซ้ำ ๆ (แนวคิดเดียวกับ longest matching) ชิ้นกลางคำขึ้นต้นด้วย ## ถ้าต่อไม่ได้ทั้งคำเป็น [UNK] บท 1.2
XOR
ฟังก์ชันที่เป็นจริงเมื่อข้อมูลเข้าเป็นจริงอย่างใดอย่างหนึ่งเท่านั้น เส้นตรงเส้นเดียวแบ่งไม่ได้ นิวรอนเดียวจึงคำนวณไม่ได้ บท 2.3
zero-shot
สั่งงานโดยไม่แนบตัวอย่างโจทย์พร้อมคำตอบ บท 3.4
β (KL coefficient) (ความตึงของสายจูง)
ตัวเลขคุมน้ำหนักของโทษ KL หรือความแรงใน DPO ค่ามากคือจูงแน่น บท 3.6
