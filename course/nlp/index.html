NLP สมัยใหม่ผ่านภาษาไทย: จากการนับคำถึง RAG

คอร์สนี้เล่า NLP เป็นเรื่องเดียว เริ่มจากการตัดและนับคำภาษาไทย ไปจนถึงการให้ LLM ตอบจากเอกสารที่ค้นมา ทุก module เปิดด้วยสิ่งที่ module ก่อนหน้ายังทำไม่ได้ ตัวอย่างหลักของทุกบทเป็นภาษาไทย และตัวเลขทุกตัวมาจากเปเปอร์หรือการทดลองที่รันซ้ำได้

ลำดับบทเทียบกับคอร์สมหาวิทยาลัยเจ็ดคอร์ส (Stanford CS224N, CMU 11-411 และ 11-711, MIT 6.8610, Princeton COS 484, UW CSE 447, Berkeley CS 288) และหนังสือ Speech and Language Processing ของ Jurafsky & Martin หัวข้อที่มีตั้งแต่ห้าในเจ็ดคอร์สขึ้นไปอยู่ในคอร์สนี้ทั้งหมด ส่วนที่ตัดออก (parsing, speech, machine translation, multimodal) ลิงก์ไปแหล่งที่สอนไว้ดีแล้ว

บทเต็มมีการทดลองและวิดีโอ ใช้กับหัวข้อที่ยังไม่มีใครสอนเป็นภาษาไทยในระดับเริ่มต้น บทสั้นให้ตัวอย่างไทยหนึ่งชุดแล้วส่งต่อไปยังคอร์สและวิดีโอที่สอนเรื่องนั้นดีอยู่แล้ว ศัพท์ที่แต่ละบทแนะนำอยู่ใน อภิธานศัพท์ และดูภาพรวม dependency ของทุกบท (รวมโพสต์นอกคอร์ส) ได้ที่ แผนผังทั้งหมด

เขียนแล้ว 33 จาก 33 บท

บทที่ M1 ข้อความ

ทำได้: ตัดข้อความเป็นหน่วย นับ จัดหมวด และค้นจากคำที่ตรงกันได้ · ยังทำไม่ได้: ถ้าคำถามกับเอกสารใช้คำต่างกันแต่ความหมายเดียวกัน การนับคำหาไม่เจอ

  • ตอน 1.1ภาษาไทยไม่เว้นวรรค ชวนรู้จักหนึ่งหน่วยบทเต็มกำลังเขียน
    • บอกได้ว่าข้อความไทยหนึ่งประโยคแบ่งเป็นหน่วยได้ห้าระดับ (code point, grapheme, TCC, พยางค์, คำ) และแต่ละระดับต่างกันตรงไหน
    • อธิบายได้ว่าทำไม "น้ำ" ที่หน้าตาเหมือนกันอาจเป็นคนละข้อความ และทำไม normalization สองแบบให้ผลคนละทิศ
    • อ่านผลของตัวตัดคำหลายตัวแล้วบอกได้ว่าทำไมไม่ตรงกัน และความต่างนั้นกระทบการค้นอย่างไร
  • ตอน 1.2โมเดลเลือกชิ้นคำอย่างไรบทเต็มกำลังเขียน
    • อธิบายได้ว่า tokenizer มีสี่ขั้น (normalize, pre-tokenize, model, post-process) และชื่อ BPE / Unigram / WordPiece บอกแค่ขั้นที่สาม
    • นับ merge แรกของ BPE บนคลังคำเล็ก ๆ ด้วยมือได้ และบอกได้ว่า WordPiece คือ longest matching แบบเดียวกับตัวตัดคำในบท 1.1
    • อธิบายได้ว่าทำไม regex ที่แบ่งตามตัวอักษรตัดภาษาไทยตรงวรรณยุกต์และสระบนล่าง และทำไม token บางตัวของ byte-level BPE (เช่นของ ๒๕๖๙) ถอดทีละตัวแล้วได้ �
    • วัด fertility ของ tokenizer บนข้อความไทยของตัวเองได้ และบอกได้ว่าผลต่างของ tokenizer กระทบค่า token และการจับคู่ของ sparse retrieval อย่างไร
  • ตอน 1.3ทายคำถัดไปจากการนับได้ไหมบทสั้นกำลังเขียน
    • นับคู่คำจากคลังข้อความเล็ก ๆ แล้วคำนวณ P(คำถัดไป | คำก่อนหน้า) แบบ MLE และสุ่มประโยคจากตารางนับได้
    • อธิบายได้ว่าทำไมคู่คำที่ไม่เคยเห็นทำให้ทั้งประโยคได้ความน่าจะเป็นศูนย์ และคำนวณ add-one smoothing ได้
    • อ่าน perplexity เป็น "ความแปลกใจ" ของโมเดล และบอกได้ว่าเมื่อไหร่เอามาเทียบกันไม่ได้
    • เทียบโมเดลที่ตัดข้อความไทยต่างกัน (คำ พยางค์ ตัวอักษร) ด้วย bits ต่อตัวอักษรแทน perplexity ต่อหน่วย
  • ตอน 1.4จัดหมวดข้อความด้วยการนับได้อย่างไรบทสั้นกำลังเขียน
    • อธิบายถุงคำ (bag of words) และคิดคะแนน Naive Bayes ของรีวิวสั้น ๆ ด้วยมือได้ ทั้ง prior, likelihood, add-one smoothing และเหตุผลที่ต้องทำใน log space
    • อ่านภาพ logistic regression ได้: น้ำหนักของคำรวมเป็น z แล้ว sigmoid (สองหมวด) หรือ softmax (หลายหมวด) แปลงเป็นความน่าจะเป็น
    • บอกได้ว่าทำไม accuracy หลอกเมื่อหมวดไม่สมดุล และอ่าน confusion matrix, precision, recall, F1, macro-F1 กับ micro-F1 ได้ถูก
    • ชี้ได้ว่าถุงคำพังตรงไหนกับภาษาไทย (ประชด ปฏิเสธซ้อน) และการเลือกหน่วย (คำหรือตัวอักษร) เปลี่ยนสิ่งที่โมเดลเห็นอย่างไร
  • ตอน 1.5ค้นจากคำทำงานอย่างไรบทเต็มกำลังเขียน
    • อธิบายได้ว่า inverted index (dictionary + postings) ช่วยให้ค้นเร็วกว่าการไล่อ่านทุกเอกสาร และทำไมไม่เก็บเป็น term-document matrix
    • คำนวณ IDF จากตาราง df ได้ และบอกได้ว่าทำไมคำอย่าง ใน และ ได้น้ำหนักต่ำโดยไม่ต้องมี stop list
    • อธิบายสองปุ่มของ BM25 ได้ด้วยคำพูด: k1 (ซ้ำมากได้เพิ่มแต่มีเพดาน) และ b (หักข้อความยาว)
    • ชี้ได้ว่าการค้นจากคำภาษาไทยพลาดตรงไหน: ตัดคำค้นกับดัชนีไม่ตรงกัน และคำต่างแต่ความหมายเดียวกัน (vocabulary mismatch)

บทที่ M2 ความหมายเป็นเวกเตอร์

ทำได้: แทนคำและข้อความด้วยเวกเตอร์ วัดความใกล้ และฝึกโมเดลให้เรียนจากความผิดพลาด · ยังทำไม่ได้: เวกเตอร์ของคำเดียวกันไม่เปลี่ยนตามบริบท และอ่านทีละคำทำให้ข้อมูลต้นประโยคเลือนหาย

  • ตอน 2.1ข้อความกลายเป็นตัวเลขได้อย่างไรบทเต็มกำลังเขียน
    • อธิบายได้ว่าทำไมเลขประจำตัวคำและ one-hot vector บอกความคล้ายของคำไม่ได้
    • นับคำรอบข้างด้วยหน้าต่าง ±2 เป็นเวกเตอร์ของคำ และอธิบาย distributional hypothesis ด้วยตัวอย่างของตัวเองได้
    • เล่าได้ว่า word2vec (skip-gram + negative sampling) ได้ตารางเวกเตอร์มาจากการทายเพื่อนบ้านอย่างไร และทำไมตารางนี้มีแถวเดียวต่อคำ
    • แยก static embedding กับ contextual embedding ได้ และบอกได้ว่าการตัดคำภาษาไทยเปลี่ยน "เพื่อนบ้าน" ของคำอย่างไร
  • ตอน 2.2ใกล้กันแปลว่าอะไรบทเต็มกำลังเขียน
    • คำนวณ dot product ความยาว และ cosine ของเวกเตอร์เล็ก ๆ ด้วยมือได้ และอธิบาย dot product เป็นภาพเงาของลูกศรได้
    • บอกได้ว่าทำไม dot product ดิบเข้าข้างเวกเตอร์ที่ยาว และทำไมหลัง L2 normalise แล้ว dot product, cosine และ Euclidean distance เรียงลำดับเหมือนกัน
    • อ่านค่า cosine ของโมเดลจริงอย่างระวังได้: เวกเตอร์อยู่ในกรวยแคบ ให้ดูลำดับภายในคำค้นเดียวกันแทนค่าเดี่ยว
    • อธิบายได้ว่าความหมายของ "ใกล้" ขึ้นกับการฝึกของโมเดล ไม่ใช่สูตร โดยยกตัวอย่างโมเดลที่ยังไม่ฝึกกับ gte-multilingual-base
  • ตอน 2.3โมเดลเรียนจากความผิดพลาดได้อย่างไรบทสั้นกำลังเขียน
    • คำนวณ forward pass ของโครงข่ายสองชั้นเล็ก ๆ ด้วยมือได้ (weighted sum → ReLU → sigmoid) และบอกได้ว่าตัวจัดหมวดของบท 1.4 คือนิวรอนหนึ่งตัว
    • อธิบาย backpropagation ด้วยคำพูดได้ว่าเป็นการส่งความผิดจากปลายย้อนทีละชั้นด้วยกติกา ความผิดที่ส่งมา × ความชันเฉพาะจุด (chain rule)
    • บอกได้ว่า weight ควรขยับทางไหนจากเครื่องหมายของ gradient และก้าวจริงคือ learning rate × gradient
    • เชื่อมได้ว่าเครื่องเดียวกันนี้ใช้กับ bag of embeddings และโมเดลภาษาแบบ feed-forward ของ Bengio et al. (2003) และรู้ว่า overfitting ดูจาก loss บนข้อมูลที่แยกไว้
  • ตอน 2.4อ่านทีละคำแล้วจำอย่างไร และ attention มาช่วยตรงไหนบทสั้นกำลังเขียน
    • อธิบายได้ว่า RNN อ่านทีละคำและส่ง hidden state ต่อด้วยน้ำหนักชุดเดียวกัน และทำไมร่องรอยของคำต้นประโยคจางลง
    • บอกได้ว่า encoder-decoder แปลประโยคอย่างไร และทำไมเวกเตอร์สรุปตัวเดียว (context vector แบบเดิม) เป็นคอขวดของประโยคยาว
    • คำนวณ attention สามขั้นด้วยมือได้: dot product → softmax → ผลรวมถ่วงน้ำหนักเป็น context ของก้าวนี้
    • อธิบาย query/key/value ด้วยภาพการค้นในพจนานุกรม และเหตุผลที่ attention คือ retrieval ที่ differentiate ได้

บทที่ M3 Transformer และ LLM

ทำได้: อ่านบริบททั้งประโยคพร้อมกัน ทายคำถัดไป สร้างข้อความ และปรับให้เป็นผู้ช่วย · ยังทำไม่ได้: โมเดลรู้แค่สิ่งที่อยู่ในข้อมูลฝึก ไม่รู้เอกสารของเรา และแต่งคำตอบขึ้นมาได้

  • ตอน 3.1attention มองไปที่คำไหนบทเต็มกำลังเขียน
    • อธิบายได้ว่าทำไม self-attention อ่านทั้งประโยคพร้อมกันได้ ต่างจาก RNN ที่ต้องเดินทีละคำ
    • คำนวณ self-attention แบบหารด้วย √d_k และใส่ causal mask บนตารางคะแนนเล็ก ๆ ด้วยมือได้
    • อธิบายได้ว่าทำไม attention ต้องมีเวกเตอร์ตำแหน่ง และ causal mask ทำอะไรกับเวกเตอร์ของคำนามไทยที่คำขยายตามหลัง (และไม่ทำอะไร)
    • อ่านตาราง attention ของโมเดลไทยจริงแล้วบอกได้ว่าชิ้นคำหนึ่งมองไปที่ชิ้นคำไหนมากที่สุด และบอกได้ว่าตัวเลขนั้นแปลว่าอะไรไม่ได้บ้าง
  • ตอน 3.2น้ำหนักร้อยล้านตัวอยู่ตรงไหนบทสั้นกำลังเขียน
    • ไล่ได้ว่าชิ้นคำหนึ่งตัวเดินผ่านหนึ่งบล็อกอย่างไร: self-attention → residual → layer norm → feed-forward → residual → layer norm แล้วซ้อนกันหลายชั้น
    • บอกได้ว่า residual กับ layer norm มีไว้ทำอะไร และทำไมบล็อกถึงซ้อนกันได้โดยไม่พัง
    • อ่านตารางนับพารามิเตอร์แล้วบอกได้ว่าน้ำหนักของ GPT-2 small อยู่ที่ตาราง embedding, attention หรือ feed-forward มากน้อยแค่ไหน
  • ตอน 3.3BERT กับ GPT ฝึกต่างกันตรงไหนบทสั้นกำลังเขียน
    • อธิบายได้ว่า causal LM (ทายชิ้นถัดไป) กับ masked LM (เติมชิ้นที่ถูกปิด) ซ่อนข้อความต่างกันอย่างไร และทำไม GPT ได้ฝึกทุกตำแหน่งแต่ BERT ฝึกเฉพาะ 15% ที่ถูกเลือก
    • บอกเหตุผลของกติกา 80/10/10 ได้ และสร้าง input ของ MLM ด้วยการเปลี่ยน token id แทนการพิมพ์ <mask> ลงข้อความไทย
    • อธิบายได้ว่าทำไมการปิดครึ่งคำไทยอาจเปิดโพย และทำไม WangchanBERTa ยังเลือกปิดระดับชิ้นคำ
    • เลือกตระกูล encoder-only / decoder-only / encoder-decoder ให้เหมาะกับงานค้นหา แชตบอต หรือแปลความได้
  • ตอน 3.4โมเดลเลือกคำตอบออกมาอย่างไรบทเต็มกำลังเขียน
    • อ่านตารางความน่าจะเป็นของ token ถัดไปได้ และอธิบายว่า decoding คือขั้น "เลือก" ในวงจร ทาย → เลือก → ต่อท้าย
    • บอกความต่างของ greedy, sampling, temperature, top-k และ top-p ได้ คิด softmax ที่ T ต่าง ๆ และชุด top-p จากตารางเล็ก ๆ ด้วยมือได้
    • อธิบายได้ว่า chat template, token พิเศษ และ system prompt เปลี่ยนข้อความที่โมเดลเห็นอย่างไร และ zero-shot / few-shot / in-context learning ต่างกันตรงไหน
    • ชี้ผลเฉพาะภาษาไทยได้: token ของคำสั่งไทยแพงกว่าอังกฤษ อุณหภูมิสูงทำให้หลุดภาษา และ no_repeat_ngram_size ทำให้สะกดผิดเพราะคำไทยกินหลาย token
  • ตอน 3.5ปรับโมเดลให้ทำงานของเราด้วยข้อมูลน้อย ๆ ได้อย่างไรบทสั้นกำลังเขียน
    • อธิบายได้ว่า fine-tuning ต่อหัวจำแนกไว้บน encoder ที่ pretrain แล้วอย่างไร และทำไมต้องฝึกไม่กี่รอบ ใช้ learning rate เล็ก และดู validation ทุกรอบ
    • เลือกได้ว่าจะฝึกแค่หัว, LoRA หรือ full fine-tune โดยนับพารามิเตอร์ที่ต้องฝึกและประมาณหน่วยความจำของ optimizer ได้
    • คิดจำนวนพารามิเตอร์ของ LoRA (2dr ต่อเมทริกซ์ d×d) และบอกได้ว่าทำไม B = 0 ตอนเริ่มและรวมกลับเข้า W ได้โดยไม่ช้าลง
    • ตัดสินได้ว่างานไหนควร prompt และงานไหนควร fine-tune
  • ตอน 3.6จากโมเดลทายคำกลายเป็นผู้ช่วยได้อย่างไรบทเต็มกำลังเขียน
    • อธิบายได้ว่าทำไม base model เขียนต่อข้อความแทนที่จะตอบ และ SFT กับ chat template ทำให้โมเดลตอบแล้วหยุดได้อย่างไร (loss เฉพาะส่วนคำตอบ)
    • คำนวณความน่าจะเป็นที่ reward model เลือกคำตอบหนึ่งจากผลต่างคะแนนด้วย sigmoid และเชื่อมกับ logistic regression ในบท 1.4 ได้
    • อธิบายบทบาทของ reference model และ β (สายจูง KL) ใน RLHF และ DPO ได้ รวมถึงอาการที่เกิดเมื่อสายจูงหลวมเกินไป
    • อ่าน DPO margin ของคู่ความชอบก่อนและหลังฝึกได้ และบอกได้ว่าทำไม margin ที่ขึ้นยังไม่ใช่หลักฐานว่าโมเดล aligned
  • ตอน 3.7วัดข้อความที่โมเดลเขียนอย่างไรบทเต็มกำลังเขียน
    • อธิบายได้ว่า BLEU นับอะไร (n-gram ที่ clip แล้ว + brevity penalty) และทำไมคะแนน BLEU ภาษาไทยต้องบอกตัวตัดคำทุกครั้ง
    • เลือกใช้ chrF กับภาษาไทยได้พร้อมเหตุผล และรู้ว่า chrF++ กับ `rouge_score` แบบค่าเริ่มต้นกลับมาขึ้นกับการตัดคำ (หรือลบภาษาไทยทิ้ง)
    • ตรวจ position bias ของ LLM-as-a-judge ด้วยการตัดสินสองลำดับ และรายงานผลด้วยกฎสลับพร้อมช่วงความเชื่อมั่น
    • ใช้ paired bootstrap ตัดสินว่าผลต่างของสองระบบบนชุดทดสอบเล็ก ๆ เชื่อได้หรือเป็นแค่ความผันผวน

บทที่ M4 ความหมายเพื่อการค้น

ทำได้: ค้นเอกสารด้วยความหมาย วัดว่าค้นดีแค่ไหน และให้ LLM ตอบจากเอกสารที่ค้นมา · ยังทำไม่ได้: งานจริงต้องทำหลายขั้นต่อกัน และคำตอบที่ดูน่าเชื่อยังผิดได้

  • ตอน 4.1เวกเตอร์ของประโยคมาจากไหนบทเต็มกำลังเขียน
    • อธิบายรูปทรงของเทนเซอร์จาก encoder (ประโยค, ชิ้นคำ, มิติ) และย่อเหลือเวกเตอร์เดียวด้วย [CLS] หรือ mean pooling ที่ใช้ attention_mask ถูกต้องได้
    • บอกได้ว่าทำไมเวกเตอร์ชิ้นแรกของโมเดลที่ฝึกด้วย MLM อย่างเดียว (เช่น XLM-R) ไม่ใช่ตัวสรุปประโยค และทำไมข้อมูลที่อยู่ในเวกเตอร์อ่านด้วยตัวจำแนกที่ฝึกได้ แต่อ่านด้วย cosine ไม่ได้
    • แยก bi-encoder, cross-encoder และ multi-vector ได้ว่าอะไรคำนวณเก็บล่วงหน้าได้ และนับจำนวนครั้งที่ต้องรัน encoder ได้
    • อ่านช่วงความเชื่อมั่นของผลต่างระหว่างสองระบบค้นหาแล้วตัดสินได้ว่า "ชนะ" หรือ "เสมอกันทางสถิติ" และตรวจเรื่องคำนำหน้า ความยาวสูงสุด และข้อมูลฝึกรั่วก่อนเชื่อผล
  • ตอน 4.2สอนเวกเตอร์ให้จับคู่ถูกได้อย่างไรบทเต็มกำลังเขียน
    • เขียน InfoNCE loss ของ batch เล็ก ๆ ด้วยมือได้ และอธิบายว่าทำไมใช้คำตอบของคำถามอื่นใน batch เป็นตัวหลอก (in-batch negatives) แทน softmax ทั้งคลัง
    • บอกได้ว่า hard negative คืออะไร หามาอย่างไร และทำไมสูตรที่ใช้ cosine ต้องหารด้วย temperature τ แต่สูตรที่ใช้ dot product ในสไลด์ไม่มี
    • อธิบาย false negative ใน batch และนับได้ว่าเกิดบ่อยแค่ไหนเมื่อบทความหนึ่งมีหลายคำถาม
    • ฝึก encoder ด้วย in-batch InfoNCE บนคู่คำถาม–ย่อหน้าภาษาไทย แล้ววัดก่อนและหลังฝึกบนชุดทดสอบเดียวกันอย่างซื่อตรง
  • ตอน 4.3metric แต่ละตัวมองไม่เห็นอะไรบทเต็มกำลังเขียน
    • คิด precision@k, recall@k, hit@k, RR, nDCG@k และ AP ด้วยมือบนรายการสั้น ๆ ได้ และบอกได้ว่าแต่ละตัวมองไม่เห็นอะไร
    • แยกได้ว่า "recall@k" ในตารางของคนอื่นหมายถึงสัดส่วน หรือหมายถึงเจออย่างน้อยหนึ่งชิ้น (hit@k) และรู้ว่าสองแบบเท่ากันเมื่อไหร่
    • อธิบายได้ว่าเอกสารที่ไม่มีป้าย วิธีสร้างคำถาม และสูตร nDCG ที่ต่างกัน ทำให้ตัวเลขเปลี่ยนได้โดยที่ระบบไม่ได้เปลี่ยน
    • อ่านผลต่างของสองระบบพร้อมช่วงความเชื่อมั่นและ histogram ของอันดับ แล้วตัดสินได้ว่า "ชนะ" หรือ "แยกไม่ออก" และเลือก k ให้ตรงกับระบบจริง
  • ตอน 4.4ให้ LLM ตอบจากเอกสารของเราได้อย่างไรบทเต็มกำลังเขียน
    • ต่อระบบ RAG ห้าขั้นเองได้โดยไม่ใช้ framework: หั่นเอกสาร ทำดัชนี ค้น top-k เขียน prompt และให้ LLM ตอบ
    • เขียน prompt แบบ RAG ที่มีคำสั่ง เอกสารที่มีหมายเลข และทางออก "ไม่ทราบ" ได้ และรู้ว่าต้องทดสอบทุกบรรทัดกับโมเดลจริง
    • วัดคำตอบด้วย EM, token F1, character F1 และ answer contained ได้ พร้อมอ่านช่วงความเชื่อมั่นแบบ paired bootstrap
    • แยกความผิดเป็น retrieval miss, reading miss และความผิดของตัววัด แล้วอธิบายได้ว่าทำไม hit@k ที่สูงขึ้นไม่ได้แปลว่าคำตอบดีขึ้น

บทที่ M5 ต่อยอด

ทำได้: ให้โมเดลใช้เครื่องมือ คิดหลายขั้น และรู้ว่าจะพังตรงไหน · ยังทำไม่ได้: บทที่เหลือของ NLP (parsing, speech, MT, multimodal) อยู่นอกเล่มนี้

  • ตอน 5.1ให้โมเดลลงมือทำหลายขั้นได้อย่างไรบทสั้นกำลังเขียน
    • อธิบายได้ว่าเอเจนต์คือวงจร สังเกต → คิด → ลงมือ และ RAG แบบบท 4.4 กลายเป็นเครื่องมือหนึ่งชิ้นในวงจรนั้นอย่างไร
    • อ่าน tool call ได้: โมเดลเขียน JSON ตาม schema แล้วโค้ดของเราเป็นคนตรวจ รันเครื่องมือ และส่ง observation กลับ
    • ชี้จุดพังของเอเจนต์ได้ ได้แก่ ความผิดพลาดทบต้น (p^n) เลือกหรือไม่เลือกเครื่องมือ กฎหยุด และคำสั่งแฝงในข้อความที่ค้นมา
    • วัดเอเจนต์จาก trace ได้ ทั้งการเลือกเครื่องมือและความถูกต้องของอาร์กิวเมนต์
    • บอกได้ว่าการตรวจ "id ที่อ้างต้องเป็นส่วนหนึ่งของ id ที่ค้นได้" จับอะไรได้ และมองไม่เห็นอะไร
  • ตอน 5.2ให้โมเดลคิดนานขึ้นช่วยได้จริงไหมบทสั้นกำลังเขียน
    • อธิบายได้ว่า "การคิด" ของโมเดลคือการเขียน token ขั้นกลางก่อนตอบ และแยกสองวิธีใช้ test-time compute ได้: คิดยาวขึ้น กับถามหลายรอบแล้วโหวต (self-consistency)
    • ทำ majority vote บนคำตอบภาษาไทยได้ถูก รวมถึงแปลงเลขไทยและตัดหน่วยก่อนนับเสียง
    • อธิบายได้ว่าทำไมตัวตรวจคำตอบ (verifier) ทำให้ฝึก reasoning model ด้วย RLVR ได้ในงานคณิตหรือโค้ด แต่ทำได้ยากกับงานเขียน
    • อ่านผลเทียบโหมดคิดกับไม่คิดโดยดูช่วงความเชื่อมั่นและต้นทุน token ได้ และบอกได้ว่าเมื่อไรผลต่างยังเป็น "เสมอกันทางสถิติ"
  • ตอน 5.3ระบบภาษาพังตรงไหน และใครได้รับผลกระทบบทสั้นกำลังเขียน
    • แยกได้ว่าคำตอบที่แต่งขึ้นเป็นแบบ intrinsic (ขัดกับเอกสาร) หรือ extrinsic (ตรวจจากเอกสารไม่ได้) และบอกได้ว่าความเสี่ยงแต่ละแบบของระบบภาษาพังที่ขั้นไหนและใครรับผล
    • ออกแบบคู่ประโยคสลับคุณสมบัติภาษาไทย (เช่น ครับ/ค่ะ) พร้อมรายการคำที่จะนับ แล้วรายงานผลเป็นจำนวนพร้อมข้อจำกัด
    • อธิบายได้ว่าตัวกรอง regex สำหรับเลขบัตรและเบอร์โทรจับอะไรได้และพลาดอะไร (ชื่อคน เลขที่สะกดเป็นคำ เลขไทยกับ [0-9]) และทำไมต้องกันหลายชั้น
    • อ่าน licence และเงื่อนไขของโมเดลหรือชุดข้อมูลก่อนใช้ แล้วบอกได้ว่าเงื่อนไขไหนห้ามฝึกต่อ ห้ามเทียบคะแนน หรือห้ามแจกต่อ
  • ตอน 5.4หาชื่อคนและสถานที่ในข้อความไทยได้อย่างไรบทสั้นกำลังเขียน
    • ติดป้าย BIO ให้ประโยคไทยได้ และอธิบายได้ว่าทำไมต้องมีป้าย B และทำไม I ต่อจาก O ไม่ได้
    • อธิบายได้ว่า CRF ใช้ลักษณะของคำกับคะแนนการเปลี่ยนป้ายเลือกลำดับป้ายทั้งประโยค และ transformer ติดป้ายชิ้นคำแรกของแต่ละคำอย่างไร
    • วัดงาน NER ด้วย F1 ระดับ entity และบอกได้ว่าทำไม accuracy รายคำหลอกเรา
    • ชี้กับดักของภาษาไทยได้: ไม่มีตัวพิมพ์ใหญ่ ขอบคำไม่ตรงขอบชื่อ คำนำหน้าชื่อ ชื่อซ้อนชื่อ และปี พ.ศ.

บทที่ M6 ค้นให้แม่นและเร็วขึ้น

ทำได้: ต่อท่อค้นหลายขั้น เรียงผลใหม่ ผสมหลายระบบ ค้นเร็วในสเกลใหญ่ สร้างข้อมูลฝึกและชุดวัดเอง แล้วอ่าน related work ของ paper retrieval ได้ · ยังทำไม่ได้: ค้นจากภาพหน้าเอกสาร กราฟความรู้ และการค้นหลายรอบแบบเอเจนต์ อยู่ในซีรีส์อ่าน paper

  • ตอน 6.1อ่านคำถามคู่กับเอกสารพร้อมกันทำไมเรียงได้แม่นกว่าบทเต็มกำลังเขียน
    • อธิบายได้ว่า cross-encoder ต่างจาก bi-encoder ตรงที่คำถามกับเอกสารเข้า attention ด้วยกัน จึงคำนวณเก็บล่วงหน้าไม่ได้ และนับจำนวนครั้งที่ต้องรันโมเดลต่อคำถามได้
    • ต่อท่อสองขั้น ค้นกว้างด้วย BM25 หรือ dense แล้วให้ reranker เรียง top-k ใหม่ และบอกได้ว่าเพดานของ reranker คือ recall@k ของขั้นแรก
    • อ่านผล reranker บนชุดคำถามไทยพร้อมช่วงความเชื่อมั่น แยก "ชนะ" กับ "เสมอกันทางสถิติ" แล้วชั่งกับเวลาที่เพิ่มขึ้น
    • แยก reranker แบบให้คะแนนทีละคู่ (pointwise) กับแบบจัดทั้งรายการ (listwise) ได้ และบอกได้ว่า Poly-encoder อยู่ตรงกลางระหว่าง bi- กับ cross-encoder อย่างไร
  • ตอน 6.2สองระบบจัดอันดับไม่ตรงกัน จะเชื่อใครบทสั้นกำลังเขียน
    • อธิบายได้ว่าทำไมบวกคะแนน BM25 กับ cosine ตรง ๆ ไม่ได้ (คนละสเกล) และ normalize ด้วย min-max, z-score หรือขอบล่างทางทฤษฎีก่อนผสมแบบ convex
    • คำนวณ reciprocal rank fusion (RRF) ด้วยมือจากอันดับของสองระบบ และบอกได้ว่า k ทำอะไร
    • เลือกน้ำหนักการผสมจากคำถามชุด validation แทนชุดทดสอบ แล้วอ่านผลบนชุดทดสอบพร้อมช่วงความเชื่อมั่น
    • บอกได้ว่าการผสมสองระบบดันเพดาน recall@100 ของขั้นแรกขึ้น และ reranker จากบท 6.1 ได้ประโยชน์จากตรงนั้นแค่ไหน
  • ตอน 6.3บีบเอกสารเหลือเวกเตอร์เดียวแล้วเสียอะไรไปบทเต็มกำลังเขียน
    • คำนวณคะแนน MaxSim ด้วยมือจากเมทริกซ์ความคล้ายระหว่างชิ้นคำของคำถามกับชิ้นคำของเอกสาร และบอกได้ว่าอะไรคำนวณเก็บล่วงหน้าได้
    • เทียบเวกเตอร์เดียวกับหลายเวกเตอร์จาก encoder ตัวเดียวกันบนชุดคำถามไทย แล้วอ่านผลพร้อมช่วงความเชื่อมั่น
    • คำนวณพื้นที่เก็บของ multi-vector เทียบกับ single vector และอธิบายได้ว่า ColBERTv2 และ PLAID ลดพื้นที่และเวลาอย่างไร
    • วาง late interaction ไว้ระหว่าง bi-encoder กับ cross-encoder ได้ทั้งเรื่องความแม่นและต้นทุน
  • ตอน 6.4ค้นล้านเวกเตอร์โดยไม่เทียบทุกตัวได้อย่างไรบทเต็มกำลังเขียน
    • อธิบายได้ว่าทำไมการค้นแบบเทียบทุกตัว (exact) ช้าลงตามขนาดคลัง และแยก recall ของ ANN (เทียบกับ exact) ออกจากความแม่นของการค้น (เทียบกับป้ายกำกับ)
    • อธิบาย IVF (แบ่งคลังเป็นกลุ่ม แล้วค้นแค่ nprobe กลุ่ม), product quantization (บีบเวกเตอร์เป็นรหัสไม่กี่ไบต์) และ HNSW (ไต่กราฟหลายชั้น) ด้วยภาพ
    • อ่านเส้น recall–เวลาของดัชนีแต่ละแบบที่วัดบนเวกเตอร์ภาษาไทยจริง แล้วเลือกพารามิเตอร์ (nprobe, efSearch) ตามงบเวลา
    • ชั่งขนาดดัชนีกับความแม่น และบอกได้ว่าเมื่อไรการค้นแบบ exact ก็พอแล้ว
  • ตอน 6.5คำไม่อยู่ในเอกสาร จะแก้ที่คำถาม ที่เอกสาร หรือที่น้ำหนักคำบทเต็มกำลังเขียน
    • ชี้ปัญหาคำไม่ตรงกัน (vocabulary mismatch) ในคำถามไทยได้ และแยกสามทางแก้: ขยายคำถาม ขยายเอกสาร และเรียนน้ำหนักคำ
    • ทำ pseudo-relevance feedback แบบ RM3 กับ BM25 ด้วยมือ และเลือกพารามิเตอร์จากคำถามชุด validation
    • ใช้ LLM ขยายเอกสาร (doc2query) และขยายคำถาม (query2doc, HyDE) แล้วอ่านผลพร้อมช่วงความเชื่อมั่นและต้นทุนการสร้างข้อความ
    • อธิบายได้ว่า DeepCT และ learned sparse เปลี่ยนน้ำหนักคำแทนการเพิ่มคำ และเป็นทางไปสู่ SPLADE
  • ตอน 6.6bi-encoder ที่เร็วเรียนจาก reranker ที่ช้าได้ไหมบทเต็มกำลังเขียน
    • อธิบาย knowledge distillation ในงานค้นได้: ครู (cross-encoder) ให้คะแนน นักเรียน (bi-encoder) เรียนให้คะแนนตาม และบอกได้ว่าทำไม Margin-MSE เรียนจาก "ส่วนต่าง" ไม่ใช่คะแนนตรง ๆ
    • ใช้คะแนนของครูหา false negative ในตัวหลอกที่ขุดมาจาก BM25 และอธิบายแนวคิด denoising ของ RocketQA
    • อ่านผลการฝึกหลาย seed บนชุดคำถามไทยแล้วแยกผลต่างจริงออกจากความแปรปรวนของการฝึก
  • ตอน 6.7ไม่มีคู่ที่ติดป้าย แล้วคู่ฝึกมาจากไหนบทเต็มกำลังเขียน
    • อธิบายได้ว่าคู่ฝึกของ embedding มาจากไหนเมื่อไม่มีคนติดป้าย: ประโยคกับบริบทของมัน (ICT), สองช่วงจากเอกสารเดียวกัน (cropping) และคำถามที่ LLM เขียนให้
    • สร้างคู่ฝึกทั้งสามแบบจากท่อนวิกิพีเดียไทยชุดเดียวกัน แล้ววัดว่าแต่ละแบบห่างจากคำถามที่คนเขียนแค่ไหนเมื่อจำนวนคู่เท่ากัน
    • อธิบายการกรองแบบย้อนหา (round-trip consistency) ของ Promptagator และอ่านสถิติของคู่ฝึกเพื่อบอกได้ว่าเมื่อไรตัวกรองจะไม่มีอะไรให้กรอง
  • ตอน 6.8"คำตอบที่ถูก" ใน benchmark มาจากไหน และ LLM ตัดสินแทนได้ไหมบทเต็มกำลังเขียน
    • อธิบายส่วนประกอบของชุดทดสอบการค้น (คลัง คำถาม และ qrels) และบอกได้ว่า pooling ทำให้ท่อนที่ไม่มีใครเคยตัดสินถูกนับว่าผิดอย่างไร
    • ใช้ LLM ตัดสินความเกี่ยวข้องตามพรอมต์ของ UMBRELA บน pool ภาษาไทย แล้ววัดผู้ตัดสินกับชุดควบคุมที่รู้คำตอบ และวัดความสอดคล้องระหว่างผู้ตัดสินสองตัว
    • ให้คะแนนระบบใหม่ด้วยป้ายของ LLM แล้วอ่านว่าลำดับของระบบเปลี่ยนหรือไม่ และอธิบายข้อโต้แย้งเรื่องวงจร (ผู้ตัดสินกับระบบเป็นโมเดลแบบเดียวกัน) ของ Soboroff และ Clarke & Dietz
  • ตอน 6.9อ่าน related work ของ paper retrieval ให้ออกบทสั้นกำลังเขียน
    • วางชื่อที่ related work อ้างลงบนแผนที่ได้: ใช้วิธีให้คะแนนแบบไหน (จับคำ เวกเตอร์เดียว เทียบคำต่อคำ) อยู่ยุคไหน และบทไหนอธิบายไว้
    • ถามคำถามสี่ข้อกับทุกชื่อที่ถูกอ้าง: อยู่ขั้นไหนของท่อ ให้คะแนนอย่างไร ฝึกด้วยสัญญาณอะไร และวัดบนชุดทดสอบไหน
    • บอกได้ว่าสาย REALM, FiD, RETRO และแบบจำลองการค้นก่อนยุค BERT เกี่ยวกับสิ่งที่เรียนมาอย่างไร แม้ยังไม่มีบทของตัวเอง
